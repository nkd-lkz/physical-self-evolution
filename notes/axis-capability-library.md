# Axis：仿真专家、筛选数据与部署回流

> 2026-09-30；[Axis 官方博客，2026-09-25](https://axisrobotics.ai/blogs/blog/beyond-more-tasks-axis-is-building-a-composable-library-of-robotic-capabilities)。这是团队披露的工程观察，没有开放逐回合轨迹与完整可复现方法；不是同行评审论文或本项目复现。

**一句话：** 先由仿真生成可工作的专用策略，部署产生的少量真机成功轨迹回流训练；再筛选有用且互补的轨迹，构建可组合的技能单元。

**直白地说：** 会操作一次的机器人可以继续实践，但“更强”要在**新评测回合**上证明，并统计它用了多少真机试验、人工示教和计算。

| 官方自述 | 正确口径 | 可借到 RLT 的问题 |
|---|---|---|
| 真机成功率约 22% → 52% | 初始模型依赖仿真数据；后续改进**使用真实部署产生的成功轨迹**，并与仿真数据共同训练。“零真机数据”只可用于描述初始训练，不适用于整个 RSI 循环。任务分布、试验数和不确定性在博客里不足以独立复算。 | 是否将接触失败/恢复与成功后果纳入经验后，在相同环境交互数下提升策略？仅筛成功可能造成幸存者偏差。 |
| 轻量代理模型按 utility 与 coverage 筛轨迹，子集优于全量 | 作者自述；未提供完整筛选实现与严格等预算对照。 | 用相同条数与计算量比较全量、均匀采样、成功优先、按接触事件/状态覆盖采样；固定 evaluator。 |
| 单任务 expert 近 100%，约 3–6 小时 A100、$5–10 | 美元数字是**纯计算成本**，还需少量用户数据或 agent prior；不是采集、训练、评测、真机部署的总成本。 | 每个 expert 记录适用状态集合与回退率；任务串联前先测试前一技能终态是否落在后一技能的有效范围。 |

## 项目侧试验：不要借“RSI”代替学习曲线

1. 保持现有 RLT baseline 与固定模拟器预算；存储 `episode_id / train_or_eval / task / scene_seed / physics_condition / policy_version / executed_action_prefix / before / after / validity_mask / controller / result`。仅在训练流写入经验；评测集及随机种子隔离。
2. 离线选择相同条数的历史：均匀、成功优先、接触事件覆盖、简单 utility + coverage 组合。后者的 utility 只由**训练/开发切分**得到；每轮重训小 learner 的预算相同。
3. 在新独立回合比较无专家成功率随环境交互数变化；并报告失败类型、专家控制秒数、wall-clock、加入轨迹数。留出对象/摩擦条件，再扩展到第二任务。若“成功优先”和“覆盖采样”无差别，就不宣称筛选机制的贡献。
4. 若未来加入技能串联，先测每个 expert 的起始状态支持度与交接成功率；长程任务总成功率不能由各单任务最佳分数相乘或代替实测。

这条路径和 [RPent 的验证后任务卡](rpent.md)、[RLT 三分支方案](../research/three-branch-research-plan-2026-09-30.md)分别作用于数据/参数、外部记忆和 actor 的局部动作改进，实验时应拆开变量。
