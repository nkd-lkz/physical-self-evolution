# ForceDelta-VLA：力条件动作修正蒸馏

> 核验日期：2026-09-21；阅读等级：正文方法、主实验与消融专题阅读。附录、训练配置与代码复现尚未完成。本文区分论文报告与本项目推论。

**ForceDelta-VLA: Distilling Force-Conditioned Action Corrections for Contact-Rich Manipulation** · arXiv:2609.18242v1。它与既有 FD-VLA（2602.02142）是不同工作，不能合并。[论文正文](https://arxiv.org/html/2609.18242v1)

## 1. 问题与机制

论文针对接触变化快、完整 VLA 推理慢的矛盾：缓存动作已过时，仍按原动作推进容易失败。方法把参考动作、力引起的修正、延迟引起的修正分开；它学习控制相关的响应，不要求恢复显式摩擦公式。

| 阶段 | 输入与目标 | 更新对象 |
|---|---|---|
| 时序教师 | 图像、任务、机器人状态、近期 wrench；示范监督 | 力感知教师 |
| 无力参考模式 | 学习缺失力条件，保留任务动作先验 | 无力 token 与低秩适配器；教师主体冻结 |
| 修正蒸馏 | 同上下文、状态及采样噪声下，对比有力/无力预测；另构造延迟补偿目标 | 小型修正网络 |
| 部署 | 慢速刷新参考，快速读取近期力与状态并修正 | 前向推理；未展示在线参数学习 |

机制定位与核心架构图见正文 §III、Fig. 1–3。特别要区分：**缺失力输入不等于物理上测得零力**；教师预测差也不等于真实环境中已识别的因果力学效应。[方法原文](https://arxiv.org/html/2609.18242v1#S3)

## 2. 证据与限制

论文在九个真机任务上，每方法每任务评测 20 次；平均成功率 ForceDelta 82.2%、时序教师 70.6%、ForceVLA 54.4%。部署仍需要实时 wrench 估计，来源为机器人关节力矩，不能写成无力反馈。修正网络前向 2.43 ms 与机器人命令上限 100 Hz 是两种指标。峰值接触力表仅统计成功试验，不能直接解释为全回合安全性。[§IV、Tables I–IV](https://arxiv.org/html/2609.18242v1#S4)

论文失败分析指出卡住后退让不足、需要重新接触或改变接近方向等情形。**这是作者观察到的失败模式；能否由我们的表征解决仍是待验证假设。** 对本项目最有用的是把“局部修正不够”和“缺少重试策略”分开标注，避免用同一个 physical 标签解释所有失败。

## 3. 对 RLT / Physical Token 的创新边界

以下为本项目研究分析，而非论文已证明的结论。

| 拟主张 | 受到的约束 | 更有辨识度的验证 |
|---|---|---|
| 大模型先验 + 小网络做接触修正 | 组合本身已有直接近邻 | 比较监督来源、更新机制及成本 |
| 一个紧凑 token 就是物理直觉 | 结构名称不能证明物理含义 | 隐藏物理条件变化时的可辨识性与闭环收益 |
| 动作修正更快所以更智能 | 提升可能由反馈频率、缓存年龄解释 | 匹配时序，再比较表示与监督 |
| 在线适应就是自进化 | 此工作没有证明跨回合学习；闭环响应与学习不同 | 等交互预算学习曲线、冻结更新对照、旧任务保留 |

因此，RLT 仍可作为在线学习基线；ForceDelta 是监督设计与执行时序的强近邻。不要把原 RLT 的 reference-conditioned actor 改称残差策略。若另做残差分支，应作为明确新增的方法变量。

**建议的收敛问题：在相同观测历史、参考策略、容量与执行时序下，用真实执行后果监督的紧凑状态，能否降低接触条件变化后的在线适应成本？** 单任务成功率提高是第一层；跨任务复用和保留需要独立证据，暂不以 Universal 或 RSI 作为已成立结论。

## 4. 可以立即追加的实验

这些是候选实验，不表示仓库已有结果，也不跳过现有 baseline gate。

| 实验 | 固定项与操作 | 记录指标 | 能判别什么 |
|---|---|---|---|
| 时序归因 | 同一 checkpoint 与控制器；参考额外延迟 0/100/200 ms；固定快回路频率与执行 chunk 长度 | 成功率、缓存年龄、有效执行时长、修正次数 | 收益是否主要来自及时反馈 |
| 监督归因 | 同数据、同容量、同历史输入；通用未来特征 vs 实测动作后果；若有合适教师再加教师修正差 | 预测误差、成功率、学习曲线面积 | 教师偏好与环境后果是否提供不同信息 |
| 感知归因 | 主表各方法使用相同部署传感器；带力分支单列，加入同容量力历史编码器 | 成功率、接触失败、传感器成本 | 增益来自 token 还是额外测量 |
| 更新归因 | 同起点、同交互预算，在线 actor/critic 更新开/关；评估时冻结 | 达到预注册成功阈值的交互量、失败数、跨种子区间 | 持续改进是否来自经验写回 |
| 恢复边界 | 标注滑移、卡住、未建立接触、目标识别错误；按类型报告 | 条件成功率、退让/重试率、失败持续时间 | 局部调节与任务级恢复各解决多少问题 |

执行顺序：先对已跑通 RLT 的一个稳定接触任务做时序诊断；再在共用离线数据上做监督归因；有信号后扩展任务与随机种子。额外延迟是诊断变量，不能改变原 baseline 主表设置后继续称其为原版复现。

如果 RoboTwin 当前没有可信、同步且部署可得的 wrench，就先完成视觉/本体历史版本。模拟器接触真值可作为训练标签或 oracle 上界，必须单列，不能悄悄作为普通 actor 输入；缺少力感知教师时，“教师修正差”实验应标为待实现，不冒称复现 ForceDelta。

## 5. 哪些结果允许哪些结论

- 后果预测更好而控制无改善：只能说明监督学到了可预测信息，尚未证明控制价值。
- 加力历史后所有方法同幅提升：优先归因于观测增强，而非专用 token。
- 匹配延迟后优势消失：贡献应收敛到执行机制，不能宣称表征创新。
- 同预算在线学习更快、冻结更新组无相同增长：支持经验驱动适应；还需排除更多更新步数与更强初始化。
- 新任务迁移成立且旧任务不退化：才进一步讨论可复用物理状态；同任务新 seed 不等于新任务。
