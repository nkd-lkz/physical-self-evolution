面向物理交互的
机器人自我改进

这是这个聊天框的“科研操作系统”，不是论文收藏夹。所有论文、随想、工程进度都围绕同一条主线： 机器人如何把一次真实物理经历，转化为下一次更好的行动，并最终形成可持续复用的经验闭环？

当前阶段目标：以 RLT 为技术起点，在 RoboTwin / RoboTwin2 与 RoboDojo 建立覆盖不同接触机制的可重复 baseline； 先完成 reference → RLT → failure diagnosis，再让实验决定究竟推进 consequence representation、value、history、failure recovery 还是 execution scheduling。

长期 Research Vision

Physically Grounded Self-Improving Robot Policies

让机器人依靠真实执行中的接触、后果、失败与恢复，持续获得新能力，而不是长期依赖人重新示范、重新标注、重新训练。

近期可验证问题

在固定或主要固定基础 VLA 时，哪些 Physical Experience、数据选择和轻量更新机制真正改善精细操作的在线适应？

最小多轮 Self-Improvement Protocol
  1. 预先冻结 task set、开发条件、final test 和总交互预算。
  2. Round 0 保存 base policy 与独立评估。
  3. 每一轮各方法获得相同新增交互预算，记录 success / failure / recovery / human intervention。
  4. 更新后只在本轮未参与训练的 initial states / conditions 上评估。
  5. 至少观察数轮趋势，并每一轮回测旧任务 / 旧 dynamics，量化遗忘。

核心指标：每单位新增交互收益、恢复成功率、无效干预比例、旧能力下降、总采集 / 人工 / 计算成本。

远期触发而非必经：共享表示（至少两个任务有同类收益）｜蒸馏回 VLA（已产生稳定高质量 recovery data）｜严格 streaming（replay 约束成为真实瓶颈）｜完整 WAM（局部后果预测已经证明长时预测必要）｜Agent/Skill 演化（失败主要来自任务分解/调用而非局部控制）。

11 · 外部观点：具身 RSI / SeeAct AI 访谈

这部分是行业 / 研究观点，不当作项目实验事实；作用是帮助确定长期 Research Vision。
最值得吸收的一句话：今天真正的机会可能不是再从零训练一个“机器人 GPT”，而是建立贯穿预训练与后训练的自进化系统：让机器人自主探索产生经验、Evaluator 判断经验、RL 把经验写回能力，并最终让经验跨本体复用。

从“及格”到“可用”

访谈把当前具身模型的关键差距概括为：少量示范可以让陌生环境中的初始泛化从 0 提到“及格”，但真实部署需要接近 99% 甚至更高可靠性。真正短缺的是失败后的自主纠错：机器人能否知道哪里错了，把这次经验留下，并让下一次策略变强。

具身 RSI 的核心定义

不是“模型自己改两行代码”，而是智能体能够利用自主探索产生的数据，结合 reward / feedback 持续提升策略，而且关键经验不是人提前提供。Rollout 中既有成功也有失败，系统要把这些经验转成下一轮学习数据。

自顶向下 × 自底向上

上层 Agent 持续提出更复杂任务，暴露底层 skill 缺口；底层通过探索、训练和验证补齐 skill；更强的底层能力又允许上层减少任务拆分、解决更长程问题。能力拓展自顶向下，能力增强自底向上，形成循环。

三套核心系统

World Engine：低成本地产生大规模可交互 rollout（可是真机、仿真或 World Model）；Evaluator / Reward Model：判断成功、进度和失败点，把 rollout 转成可学习反馈；RL / Policy Base：把这些被评价的经验真正写回策略。

Harness 的位置

无需从头训练另一个顶层大模型。上层可直接调用最强 foundation model，真正需要搭的是完整 Agent Harness：工具、skill、能力边界、memory、documents、reasoning flow，以及下面的 simulation / RL / data infrastructure。

物理世界反过来塑造模型

长期愿景不是“大模型单向吞噬物理世界”，而是把物理世界视为一个拥有 diverse environment / task / feedback 的训练场。机器人在真实交互中产生的经验未来可能反哺更大的基础模型。

为什么需要群体经验

单一本体很难支撑真正通用智能。如果机器人 A 已经踩过某类 failure，机器人 B 面对相似问题不应该重新从头探索。目标是把单个机器人自主纠错产生的经验变成跨本体可复用经验。

这份观点对当前 RLT 项目的“可用指导”与“不可直接照搬”

可用：强调 failure / recovery experience、reward/evaluator、经验闭环、跨任务/跨机器人复用；支持我们把“Physical Experience Flywheel”作为长期研究地图。

不可直接照搬：World Engine / Agent Harness / 群体 RSI 都是上位系统概念。当前第一步仍是把局部精细操作的 reference + RLT baseline 跑清楚，并用 D1–D5 证明真正瓶颈。否则系统故事会掩盖 sensorimotor 科学问题。

1. 当前应当确定什么，保留什么不确定性

1.1 统一的研究问题

建议使用工作名称：****面向物理交互的自我改进机器人策略****，英文暂用 Physically Grounded Self-Improving Robot Policies。名称表达研究对象与方向，不代表已经实现的能力或已确定的论文标题。

核心问题是：

预训练机器人策略在接触、约束和动力学变化中产生的成功、失败与恢复经验，应该怎样被利用，才能让策略以较少新增交互更可靠、更高效地完成精细操作？

第一阶段把问题收窄为：****在固定或主要固定基础 VLA 的条件下，哪些物理交互信息、数据选择方式与轻量更新机制真正改善在线适应？**** 是否最终需要改变表示、critic、动作空间或数据收集机制，由实验决定。

“Physical”在这里至少有三个可测含义：动作能否满足接触与几何约束；面对质量、摩擦、延迟等变化能否适应；失败后能否根据实际后果修正动作。仅仅增加物理变量预测头，不能证明这三项能力。

“自进化”作为长期愿景，近期使用更容易验证的“自我改进 / 在线适应”。要声称自我改进，至少应展示****旧策略执行 → 新经验 → 策略更新 → 独立评估提升****；要声称持续自我改进，还应展示多轮积累、保持旧能力以及明确的人类投入。

<a id="rlt"></a>

4. RLT 如何作为可信的技术起点

4.1 原论文的核心机制与可继承内容

RLT 利用 VLA 的紧凑读出和参考动作支持小型在线 actor–critic。读出通过重建 VLA 特征学习；离线阶段可同时做任务 SFT，在线阶段冻结 VLA 与读出。actor 条件化于参考 chunk 并受动作锚定约束，输出 Gaussian action chunk；critic 使用 chunk 级 TD。论文包含参考动作 dropout，并分别考察关键阶段与完整任务。原论文 IV–VI 节[^1]

原实验使用 π0.6，当前项目使用 π0.5；原论文 C=10 的短动作块与本地曾使用的 K=1 也不同。这些差异不妨碍开展研究，但必须在复现记录中明确，不能把移植后的数值直接称为原实验复现。

可以保留的研究框架是：

```mermaid

flowchart LR

    O[图像、指令与执行反馈] --> V[固定基础 VLA]

    V --> Z[紧凑表示]

    V --> R[参考动作]

    Z --> A[轻量策略]

    R --> A

    A --> E[环境执行]

    E --> D[实际动作、后果与奖励]

    D --> Q[价值学习与策略更新]

    Q --> A

```

这个框架既允许研究表示，也允许研究价值、动作、数据与执行时机。RLT 没有直接证明其读出缺失物理信息，因此“RLT 不懂物理”只能作为待检验假设，不能直接写成论文结论。

4.2 基线命名与版本差异

建议维护两个明确标签，避免再用同一个 B0 混指多种算法：

| 标签 | 定义 | 使用方式 |

|---|---|---|

| ****RLT-π0.5-adapted**** | π0.5 和目标环境上的算法移植，尽量保留原文读出、参考条件化、动作锚定和 chunk TD | 目标主基线；差异表必须齐全 |

| ****Local-Residual**** | 本地已有加法残差、K=1 或特定切换逻辑的配置 | 调通管线与实用对照；明确是本地变体 |

若首轮只能跑通 Local-Residual，应如实汇报，随后补齐 RLT-π0.5-adapted。无需为了命名同时维护两套完整训练基础设施，但不能用一种算法的名称掩盖另一种动作参数化。

| 核查项 | 复现记录要回答的问题 |

|---|---|

| 基础模型 | 使用哪个 π0.5 checkpoint？任务 SFT 数据与训练量是多少？ |

| 读出 | 从哪层特征提取？编码器、解码器、维度与重建目标是什么？ |

| 梯度 | 重建损失是否更新 VLA？可选 SFT 是否更新 reference？在线阶段冻结哪些参数？ |

| actor | 输出完整 chunk 还是加法残差？探索噪声、限制与 dropout 如何设置？ |

| critic | 状态、动作及目标网络怎样构造？更新算法是否与原文对齐？ |

| 时间 | VLA 预测长度 H、实际执行 C、控制频率、返回观测频率分别是多少？ |

| 数据 | demo、reference rollout、RL rollout 与人工介入如何进入 replay？ |

| 奖励 | 成功奖励、终止、稀疏/稠密版本及任何 shaping 如何定义？ |

| 任务阶段 | 全程 RL、关键阶段 RL 还是基础策略前缀加 RL？切换依据是否使用特权信息？ |

| 验证 | 固定哪些 seeds？如何选 checkpoint？比较的预算单位是什么？ |

4.3 公平比较物理监督时的额外约束

为了比较后果监督与普通读出的差异，先选定共同任务 reference，再让各组从同一冻结 VLA 特征训练同构读出。在线阶段首轮冻结读出，只训练同等规模 actor–critic。这样才能把“训练信号的收益”与“基础策略又做了一轮 SFT”的收益分开。

这不是要求整个项目永远冻结 VLA。若后续研究蒸馏或联合更新，应作为单独条件，报告参数量、数据、算力与旧能力保持。

4.4 chunk 与 transition 的实现检查

以下是目标环境移植时的验收规范，不是本次已实现的代码：

[

y_t=\sum_{i=0}^{c_t-1}\gamma^i r_{t+i}

 + m_t\gamma^{c_t}\bar Q(x_{t+c_t},a'),

]

其中 (c_t) 是这条转移****实际执行****的控制步数，(m_t) 表示按照任务终止/截断定义是否允许 bootstrap。若在中途成功终止，不能仍按完整 C 步处理；自动 reset 不能把下一 episode 的初态当终态。时间限制截断的处理要与 finite-horizon 定义一致，并保留 final observation。

比较不同 C 时，同时报告控制步数、策略决策次数和真实/仿真秒数。如果每个决策都更新相同次数，C=1 与 C=10 的每控制步训练量不同，不能声称预算天然相等。折扣也应按相同物理时间尺度解释。

本地历史检查曾指出策略切换开关与 `num_action_chunks` 存在一致性风险；属于待核查配置问题，不能据此宣称已经发生训练故障。长训练前要读出最终生效配置，验证接管时机、实际执行长度和奖励聚合。

4.5 baseline 完成的标准

“程序能启动”只算 smoke。完成一项任务 baseline 至少需要：reference 与 RLT 均完成独立评估；一段可解释的学习曲线；有效的训练与评估 seeds；可恢复的权重和配置；原始 episode 结果及失败视频；没有未解释的动作/时间/输入差异。

baseline 未超过 reference 也可以是可信结果，前提是已经排除实现问题并报告预算和不确定性。“复现通过”不应等价于筛选出一个赢的 seed。

优先选择满足以下条件的任务：可重复 reset；可获取足够 reference 数据；success 可解释且能人工抽查；失败集中在相关物理阶段；关键物理参数可控；能记录实际动作与后果。尚不满足条件的任务留在候选池，不因名字贴近“精细操作”就投入长训练。

6.5 预算、统计与评估纪律

开发阶段可从每配置 3 个训练 seeds 起步，最终按方差与预期效果决定是否扩大至 5 个或更多。每个 checkpoint 在固定、独立的评估初态上测试。30 episodes 可作先导画像，但不是充分统计保证；即使忽略训练方差，成功率约 50% 时，30 次独立试验的标准误约 9 个百分点。

报告训练 seed 间差异、每任务结果和置信区间。重采样应考虑“训练 seed—评估 episode”的层级，不能把同一个模型的几百个 episode 当成几百次独立训练。微小收益在区间高度重叠时应记为尚不确定。

预算至少分为：原有示教、新增在线控制步、分支/恢复采集、人工介入、梯度更新、VLA 调用与墙钟时间。比较 C 或异步执行时，按相同控制时间和调用/计算预算分别看结果。

学习曲线面积建议在共同控制步预算上积分并除以预算，使纵轴仍对应平均学习期成功率。达到目标成功率的步数需预先给定目标与评估规则；未达到写“预算内未达到”。耗时联合报告成功与超时，或使用 successes / total execution time，避免只统计成功 episode 造成幸存者偏差。

| 工作 | 已有机制 | 与当前候选的接近程度及边界 |

| PIN-WM，2025 | 可微物理与视觉重建支持非抓持操作的世界模型与系统辨识 | 适合理解显式物理路线；不是只加一个辅助头的等价方法[^28] |

这一组文献表明，****“加入 physics loss”不足以单独支撑新颖性****。可能值得推进的具体问题是：在同等输入与预算下，哪种后果监督真正提高候选动作区分，并减少新物理条件下的在线交互需求？这是本报告提出的研究问题，尚不是已证实空白。

还要避免两个过强推论。第一，下一状态可预测并不保证得到充分 Markov 状态；第二，在专家分布上预测准确不代表能预测策略偏离专家后的后果。表示研究应在失败附近、新动作和未见物理条件上验证。

7.3 物理信息可以用于价值，而不只用于重建

| 工作 | 已有机制 | 应当比较的内容 |

|---|---|---|

| V-GPS，CoRL 2024 | 用离线学到的价值函数重排基础策略动作，可复用于不同策略 | 候选筛选是强对照；候选里有没有好动作决定上限[^14] |

| Asymmetric Actor Critic，2017/2018 | 训练 critic 使用完整状态，actor 使用图像 | 特权 critic 本身不是新方法；训练与部署输入要分别声明[^15] |

可比较的四种用途是：仅以普通观测学 RL；用物理量监督表示；让物理量只进入训练期 critic；把动作收益或排序蒸馏到部署可用输入。比较时应明确额外训练信息和成本。

特权 critic 是诊断工具，不是保证更优的 oracle。若普通输入无法区分两个隐藏动力学状态，强行要求其精确恢复物理真值也可能无解；应考虑历史、条件期望或不确定性。

各组的数据权限应在实现前明示：

| 信息 | 监督标签 | 训练期 critic | 部署策略 |

|---|---|---|---|

| 图像、语言、真实可用本体反馈 | 可用 | 可用 | 可用，各比较组输入对齐 |

| 历史动作与反馈 | 可用 | 按实验条件 | 按实验条件，单独报告历史收益 |

| 仿真物体真值、接触、质量/摩擦 | 可用 | 仅明确标注的特权组允许 | 主方法不直接使用 |

| 未来真实观测与结果 | 可用于训练目标 | 可构造训练目标，不能当作当前决策输入 | 不可使用 |

| 真机外部测量或人工失败标注 | 可作带置信度标签 | 按实验条件与成本声明 | 仅在明确允许该传感/服务的条件下使用 |

特权 critic 扩展了旧方案“物理信息只作 target”的设定，应单列实验组；不能悄悄加入原 baseline。

同样，****残差有界或基础模型冻结，并不保证整套部署策略保持原有能力****。附加模块仍可能在原本成功的状态错误介入，因此需要旧任务与成功状态的回归评估。

8.3 同状态候选实验怎样做才有解释力

设 a⁽⁰⁾ 为基础动作，a⁽¹⁾…a⁽ᴷ⁾ 为合法局部修改。执行候选后使用固定后续策略 π_follow，估计：

    Δ_i(s) = J(s, a⁽ⁱ⁾; π_follow) − J(s, a⁽⁰⁾; π_follow)

这个量是****给定候选集合、后续策略和时间范围的干预收益****，不是全局最优 advantage。基础动作也可能已经正确，因此候选集合必须含“不修正”；若考虑干预成本，成本系数应预先设定并报告敏感性。

先用约 20–40 个独立接触前状态、每个少量候选调通过程；它们只用于工程筛选。正式规模依据方差决定。状态恢复要涵盖机器人、对象、速度、控制器、任务逻辑、随机状态及模拟器可恢复的内部状态，并实测重复前缀是否得到一致结果。

若不能精确恢复，使用同初态前缀回放并量化分支起点差异，不能仅把物体 pose 设回就声称反事实公平。所有分支、重复试验及前缀回放计入数据采集成本。随机环境下，用单次 rollout 的最大值选择“oracle”会乐观偏置，需通过独立重复试验评估候选价值。

8.4 物理后果监督的最小方案

若诊断支持表示不足，可用当前可获得观测历史 h_t 产生紧凑表示 z_t，再用候选执行序列预测后果：

    z_t = f_phi(h_t)

    predicted_consequence = g_omega(z_t, executed_action_sequence)

第一版只选一两个决策相关目标，例如对象相对位移与接触建立。总目标可为重建项加带有效性 mask 的 Huber/BCE 项；每个目标按训练集统计量归一化。辅助头必须通过可训练表示产生输出，验证梯度确实到达 readout；冻结 VLA 不等于冻结 readout。

注意几项实现边界：

- 选动作前的状态表示使用截至 t 的信息；候选动作可以进入动作条件预测头或 critic，未来真实观测只能作为标签。

- 首先考虑从冻结 VLA 的未压缩特征学习读出。若只在已经丢失信息的固定 token 后接 MLP，不能假设它能恢复缺失细节。

- 与仅动作、仅状态、任务阶段和一般未来 latent 预测比较，检查模型是否实际利用状态—动作交互。

- 目标必须对应真正执行的整个动作序列与时间区间，不能用首个动作或均值代表不同的执行轨迹。

- 接触事件可能发生在保存帧之间，应按控制区间聚合；冲量不能未经单位与时间校验直接解释成力。

- 探针提升后还要做小规模在线比较；预测更准不会自动推出控制更好。

只有物理监督在同等数据与输入下产生稳定增量，才值得继续讨论“共享物理表示”。若新增标签只改善任务阶段识别，或 actor/critic 根本不利用新表示，则应修正解释或转向。

8.5 价值、数据与执行路线各自的最小版本

****价值/收益路线：**** 先训练候选回报排序或收益回归器，再测真实闭环选择效果；与失败概率门控、随机选择、固定残差以及相同候选数的价值引导对照。若直接排序已有效，不必先造一个复杂生成模型。

****恢复数据路线：**** 先验证约 10 个失败状态可否被专家或规划器恢复，保留失败前缀、恢复动作与结果。普通专家新增数据与恢复数据按新增帧数和实际采集成本分别对齐；成功恢复不能只从容易状态中筛选后隐藏失败尝试。

****执行路线：**** 首先验证固定执行长度的效果。当前 chunk 边界返回新观测与执行中中断是不同接口；自适应 horizon 要记录每条 transition 的实际长度，异步执行还要对齐在途动作与策略版本。不要把它估成只增加一个预测头。

8.6 继续或转向的规则

| 观察 | 下一步 |

|---|---|

| 候选最好动作也无法改善 | 改候选、接管时机、控制空间或恢复数据 |

| 候选有收益，但普通观测无法判断 | 查历史、传感频率、标签歧义和分支误差 |

| 真实反馈有效，物理 loss 无增量 | 优先反馈与历史路线，保留同输入对照 |

| 表示探针提高，控制没有提高 | 检查表示使用、critic 与优化；结论限定为当前预算下无控制收益 |

| 新增恢复数据已解释多数改善 | 转向数据获取与经验复用问题 |

| 缩短 C 就显著改善且成本可接受 | 先以执行调度为强基线，再判断复杂模块价值 |

| 物理监督在多任务同预算稳定有效 | 深入机制、迁移与真实接触验证 |

| 不同 seeds 的波动覆盖了效果 | 扩大有针对性的重复，或把结论记为不确定 |

停止条件不应是“损失没降到指定小数”或“一次没赢就放弃”。每轮先约定问题、预算、主要指标和允许的解释，再决定追加数据是否能解决不确定性。

<a id="self-improvement"></a>

9. 怎样把“自进化”变成可验证实验

9.1 区分三种改进机制

| 机制 | 改变什么 | 合适的评价方式 |

|---|---|---|

| 历史条件适应 | 参数不变，输入上下文改变 | 同一任务中出现扰动后的恢复；历史重置对照 |

| 在线策略适应 | 更新轻量策略、critic 或其他小模块 | 交互预算—性能曲线、新条件适应速度 |

| 经验回写 | 使用新经验更新基础 VLA | 回写前后新旧任务表现、人工数据成本与遗忘 |

仅给策略拼接历史，不等于它已经具备通用 in-context learning；应通过未见变化和历史干预实验检验。第一阶段聚焦轻量在线适应，经验回写参考 PLD 等工作后再决定。PLD[^17]

9.2 一个可控的多轮改进协议

在 baseline 与一个候选方法稳定后，可做以下小型闭环：

1. 固定任务集合、训练条件、开发集、最终测试集与总交互预算。

2. Round 0 保存基础策略与初始评估。

3. 每轮给所有方法相同新增采集预算，记录成功、失败、恢复及人工介入。

4. 更新策略，再在不参与本轮训练的数据/初态上评估。

5. 至少观察数轮趋势，并在每轮重新评估旧任务/旧动力学条件。

每轮用于调整方法的是开发集。最终测试条件预先封存；若保留各轮 checkpoint，可在设计固定后统一评测最终测试曲线，避免每轮根据测试结果重新挑方法。

必要对照包括冻结不更新、常规 RLT 持续训练、相同新增量的普通采集，以及候选经验选择方法。多轮胜过 Round 0 本身并不能说明采集机制更优，因为常规继续训练也会使用更多经验；优势需要在累计预算相同处比较。

核心指标是每单位新增交互的收益、失败恢复成功率、无效干预比例、旧能力下降、总采集/人工/计算成本。若每轮都由人调参、挑数据或接管，要计入并准确称为有人参与的自我改进。

9.3 外观、动力学与持续变化分开设计

同任务内先扫描单个因素：初始对准误差、质量、摩擦、控制延迟或控制器增益。训练范围、验证范围和测试范围预先分开；同时监控任务是否仍然物理可解。

外观随机化作为视觉泛化对照；不能把质量变化与纹理变化都合成一个 OOD 分数。持续学习可进一步考虑 A → B → A 的条件切换，区分适应新环境与回到旧环境后的能力保持。

迁移实验还要写清：哪些参数复用、哪些重新训练、接收多少目标数据、是否接收目标物理标签。冻结表示迁移到新任务与在新任务重新训练全系统回答的是不同问题。

9.4 真机如何加入

双仿真任务稳定后，优先选择一类最能检验最终主张的真机任务。例如方法改善卡滞恢复，就选择可重复的插入误差；方法改善摩擦适应，就选择可控对象与表面变化。真机任务数量应服务于主张，第一阶段不必预设大型任务套件。

策略输入与评测工具分开声明。可以只给策略 RGB 与本体反馈，同时用外部装置测接触质量；没有测量力的设备和校准，就不报告峰值力下降。真实反馈缺失时必须用 mask 和明确字段表示，不能填零当真实无接触。

真机阶段记录每次 reset、人工介入、失败处置和有效采集时间，保留基础策略回退机制。这里的关键不是声称“完全自主”，而是证明在实际投入约束下，经验确实改善下一次行动。

9.5 远期方向的触发条件

| 扩展 | 何时值得启动 |

|---|---|

| 共享表示 | 至少两个任务显示同类监督有用，且迁移能检验方法主张 |

| 蒸馏回 VLA | 轻量适应已经产生稳定高质量恢复经验，且部署希望去掉外部模块 |

| 严格 streaming | replay 系统稳定，设备内存/经验存储成为明确问题，且能审计每条经验的使用次数 |

| 完整 WAM | 小型后果预测显示长期规划确有价值，而非只需局部动作修正 |

| Agent / 技能代码演化 | 失败证据主要来自任务拆解与技能组合，超出局部控制问题 |

它们不应被排成“每项都必须完成”的必经链条。

旧随想里只有缩写或缺少完整出处的工作，例如 RICL、ICWM、Zeva，暂不放进核心阅读序列。需要先确定具体论文及适用设定，再决定是否与当前 baseline 问题相关。宏观的 System 1/System 2 趋势判断和未核验产品性能数字，也不作为论文实验动机的事实证据。


示例：

【论文】RLT，2026，原文链接  

【问题】怎样利用预训练 VLA，让小型在线 RL 有效改善精细任务？

【动作】完成复现差异表，先不加新物理 loss。

群讨论只需要挑出一个最有价值的问题，不要求每天都形成新方法。每周把笔记汇总为“新增证据、被削弱的假设、下一项实验”三列，即可让阅读积累进入研究决策。

12.1 从 baseline 开始保留可复用的经验

下列是建议的数据契约，不意味着当前所有字段都已实现。先保证核心字段完整，再按任务补充物理诊断；原始视频和高频物理量可保存为关联 sidecar，避免所有内容都塞进 learner 内存。

| 类别 | 建议字段 | 用途 |

|---|---|---|

| 身份与版本 | task、episode、seed、env commit、policy checkpoint/version | 复现、跨平台对齐、定位权重更新 |

| 时间 | observation timestamp、control dt、chunk 生成/执行时间 | 检查延迟、因果顺序和实际后果 |

| 策略输入 | RGB 引用、语言、部署状态与历史索引 | 重建当时可获得的信息 |

| 动作 | reference、actor proposal、clipped/executed action、实际执行长度 | 区分计划与执行，支持纠偏收益分析 |

| 反馈 | q_cmd、q_real、可用 qvel、有效性 mask | 执行误差与历史适应 |

| 物理 sidecar | 对象/TCP 相对位姿、接触事件、已校验冲量 | 训练标签与诊断，默认不直接输入部署 actor |

| 结果 | reward、success、termination、truncation、final observation | 正确 TD 与完整评估 |

| 恢复 | failure type、介入来源、恢复动作、恢复结果 | 数据选择与自我改进分析 |

| 成本 | 推理、更新、reset、人工时长与 VLA 调用数 | 样本效率和真实系统效率 |

| 分支 | parent state/episode、候选编号、复位误差、重复试验编号 | 区分相关样本与候选评估 |

本地状态的命名尤需统一：drive target 写成命令状态，实际关节位置写成真实反馈。归一化后内部 padding 维度也要与真实 14 维机器人动作区分。未知/未记录不等于零，任何缺失物理标签都配有效性 mask。


我们的长期方向是让机器人利用物理交互经验持续改善操作能力，目前以 RLT 作为轻量在线学习的技术起点。已有工作完成了原生 hammer 环境、示教与物理标签管线，并生成了 π0.5 的两万步 SFT 权重；接下来首先评估这些权重，明确基础策略到底在哪些阶段失败。
