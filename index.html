面向物理交互的
机器人自我改进

核心问题：机器人如何把一次真实物理经历，转化为下一次更好的行动，并最终形成可持续复用的经验闭环？

当前执行重点不是继续发明新 idea，而是先把 RLT Multi-task Benchmark 做扎实： 在 RoboTwin2 上建立多个不同接触机制任务的 Reference → RLT → Evaluation 闭环；hammer 保留为已有资产丰富的 pilot task，但不再让单一 hammer 牵着整条科研路线走。

01 · 科研主线

路线更新：从“Physical Token 探索”切换为四阶段、证据驱动推进。

Phase 0 · RLT Multi-task Benchmark当前阶段：RoboTwin2 多任务复现 RLT，统一任务接口、评估与日志。
Phase 1 · Failure Diagnosis定位真正瓶颈：observability / candidate / critic / data / execution。
Phase 2 · Physical Experience Representation只有诊断支持后，才研究 consequence / value / history / correction。

长期 Vision

Physically Grounded Self-Improving Robot Policies

让机器人利用真实执行中的接触、动作后果、失败与恢复，持续获得新能力，而不是长期依赖人重新示范、重新标注、重新训练。

近期可验证目标

建立一个能持续承载算法创新的 VLA + Online RL 多任务实验台。

先回答“RLT 在哪些物理机制任务上有效 / 失效、为什么”，再回答“我们应该改哪里”。

03 · Phase 0：RLT Multi-task Benchmark

当前最高优先级。

打开详细执行文档

Task 0 · Hammer（保留）

已有工程资产最完整，适合做 reference / RLT pipeline 的 regression 与 smoke。

定位变化：从“主故事任务”降为 pilot task，不再单独支撑科研结论。

Task 1 · Precision Contact

优先选择 RoboTwin2 中一个局部对准 / 点接触任务，例如 bell / button 类；进入正式实验前先检查 reward、success 和接触物理。

Task 2 · Constrained Contact / Insertion

再选择一个插入 / 约束接触 / sustained contact 任务，与 hammer 形成互补物理机制。

RLT Baseline Contract：必须核对的 10 项
  1. 基础模型：π0.5 checkpoint、SFT 数据与训练量。
  2. 读出：从哪层 hidden states 取；encoder / decoder / reconstruction。
  3. 梯度：Stage 1 哪些参数更新；Online 阶段冻结哪些。
  4. Actor：完整 chunk 还是 residual；exploration、action limit、reference dropout。
  5. Critic：状态 / 动作输入、target network、TD backup。
  6. 时间：预测 H、实际执行 C、control Hz、policy decision Hz。
  7. 数据：demo / reference / RL rollout / intervention 如何进入 replay。
  8. 奖励：success / terminal / timeout / shaping。
  9. 阶段：全程 RL、critical phase 还是 base-prefix + RL。
  10. 验证：train/eval seeds、checkpoint selection、控制步 / 决策次数 / wall-clock / VLA 调用预算。
Phase 0 完成标准：至少 3 类物理机制任务；每个任务都有同一套 Reference / RLT 评估接口、learning curve、固定 seeds、episode-level raw metrics、失败视频和配置可恢复性。代码能启动只算 smoke。

04 · Phase 1：Failure Diagnosis

Multi-task baseline 之后再做，不把所有失败都归结为“缺 physics”。

实验最小设计要回答的问题
D1 · 输入与历史command target → + actual q → + short history缺“物理知识”，还是没看到真实执行？
D2 · Candidate Headroom同状态：不修正 + 少量合法 candidates；后续策略固定Reference 附近到底有没有更好的 correction？
D3 · 监督用途reconstruction vs future latent vs physical consequence vs correction benefitPhysics 应进入 representation、value 还是 correction？
D4 · 数据覆盖同新增预算：普通 expert vs failure-recovery改进来自算法，还是因为终于覆盖失败附近？
D5 · 执行长度C=1/5/10，记录 control Hz、VLA 调用、真实执行范围主要失败是不是 chunk 太长、反馈太慢？

05 · Phase 2：Physical Experience Representation

这是候选研究阶段，不是当前默认路线。只有 Phase 1 给出证据后才启动。

Action Consequence

研究 action → state / contact / relation change 是否比普通 latent reconstruction 更有控制价值。

Value-Oriented Physics

把 privileged physics 用作 candidate ranking / critic teacher，而不是直接给 actor 作弊。

Execution History

如果 actual q + short history 已经解释大部分收益，则优先解决 observability，而不是发明新 token。

打开完整观点与研究框架

从“及格”到“可用”

当前具身模型更大的缺口是部署可靠性与失败后的自主纠错，而不只是一次成功。经验能否被留下并让下一次策略更强，是自我改进的核心问题。

World Engine · Evaluator · Learning

World Engine 产生经验；Evaluator / Reward Model 判断经验；RL / Policy / Skill system 把经验变成能力。

Top-down × Bottom-up

上层复杂任务暴露底层 skill gap；底层探索与学习补能力；能力变强以后，上层可以解决更长程任务。

Physical World → Model

长期不只是模型进入物理世界；物理世界产生的 diverse environment / task / feedback 也可能成为下一代模型持续训练的数据源。

Harness 不会消失

机器人没有 Ctrl+Z。Tool、Skill、State、Verifier、Recovery、Safety、Compute 与 Communication 都需要运行时系统管理。

群体经验

机器人 A 已经踩过的坑，机器人 B 不应该从头探索。长期真正要 scale 的是自主纠错产生的共享 Physical Experience。

知识库 · 科研假设池

Idea Pool 不是 Roadmap。每个想法必须有实验触发条件。

R0 · Action Consequence

学习 decision-relevant action effect，而不是泛化地“预测 physics”。

触发：D3 consequence 明显优于 generic future latent

R1 · Value-Oriented Physics

Privileged physics 先服务 critic / candidate ranking，再决定是否蒸馏回 actor。

触发：D2 有明显 candidate headroom

R2 · Correction Benefit

学习“这次是否值得纠偏、哪种 correction 更好”。

触发：有 correction headroom 但误干预明显

R3 · Execution History

actual q / history / contact trace 可能比新 token 更重要。

触发：D1 history 增益大

R4 · Failure Recovery Data

失败附近的数据覆盖可能是最关键资源。

触发：D4 recovery data 明显胜出

R5 · Adaptive Execution

学习何时缩短 chunk、何时 replan、何时 async correction。

触发：D5 短 C 解决主要失败
