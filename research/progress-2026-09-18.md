## 1. 今日结论

9 月 18 日的核心结果不是“性能已经提升”，而是进一步明确了 **reference capability** 与 **online RLT stability** 两个独立问题：

1. **新 train450 Stage1 的 10k checkpoint 已完成同协议双卡复测，两次均为 22/40（55%），eval 正常结束。** 聚合指标完全一致，支持该 checkpoint 在当前 eval40 协议上的聚合可复现性。
2. **新 Stage1 训练已停止在约 10.8k，而非完成 30k。** 当前完整 checkpoint 只有 5k 与 10k；10k 是当前新数据路线的 development candidate，不是最终 reference。
3. **旧 clean50/12k reference 的 B0 Stage2 随训练明显退化，已主动停止。** 早期 20-seed 评测约 45%，后期降至约 15%；因此当前不能继续把“更多在线更新”当作默认正确方向。
4. **当前没有 online RL 收益，也没有 Physical Token / physics grounding 收益。** 下一步优先做 BC-only / reference-consistency / action-deviation 诊断，再决定如何重建 B0。
5. **RoboDojo 状态保持 D3/D5 工程验收通过，D6 reference-only adapter 与后续 online RL 尚未完成。**

## 2. 新 train450 Stage1：10k checkpoint 能力验收

### 2.1 训练配置与停止状态

新 Stage1 使用：

- generic `pi05_base` 初始化；
- train450 / eval40 数据；
- joint VLA task adaptation + RLT reconstruction；
- H50；
- global batch 64；
- `rlt_alpha=1`；
- 原计划最大 30k optimizer steps；
- 每 5k 保存 checkpoint。

迁移前最后完整训练日志约为：

> **10823 / 30000 steps（36.1%）**

当前保留的完整 checkpoint 为：

- 5k；
- 10k。

停止后的非零 launcher / stage exit 只表示训练被主动终止，不表示 30k 已完成或 run 正常收敛结束。

停止前训练健康度记录约为：

- total loss ≈ 0.05317；
- RLT reconstruction loss ≈ 0.05236；
- VLA loss ≈ 0.000808。

这些只说明离线目标仍在被优化，不能替代闭环能力评估。

### 2.2 10k eval40 双卡复测

10k checkpoint 使用完全一致的闭环协议做了两次独立设备运行：

- H50/C50 native_macro；
- same eval40；
- fixed task prompt；
- fixed action-sampling seed；
- same train450 normalization；
- eval 正常退出。

两次聚合结果均为：

| metric | run A | run B |
|---|---:|---:|
| success | 22 / 40 | 22 / 40 |
| success rate | 55% | 55% |
| failure | 18 / 40 | 18 / 40 |
| return | ≈ 0.55 | ≈ 0.55 |
| mean step reward | ≈ 0.002875 | ≈ 0.002875 |
| mean episode length | ≈ 196.25 | ≈ 196.25 |

### 2.3 当前允许的解释

可以说：

> **train450 Stage1 10k 在当前 eval40 开发协议上达到 22/40（55%），且两次跨设备复测的聚合指标一致。**

但暂时不能说：

- 55% 显著优于旧 clean50/12k 的 50%；
- 数据扩容已经证明提升泛化；
- 10k 是最终最优 checkpoint；
- 40+40 可合并成 80 个独立 seeds；
- Stage1 10k 的 RL Token representation 已优于旧 representation。

原因：

1. eval40 与 train450 seeds 不重叠，但包含旧 20-seed development cohort 中的 19 个 seeds；
2. 旧 12k 是 20-seed 评测，当前 10k 是 eval40，不是完全 matched cohort；
3. 当前只确认聚合一致，尚未完成逐 seed / 逐轨迹一致性核对；
4. reference rollout 主要验证 VLA 闭环动作能力，不能单独验证 `z_rl` 对 Q-learning 的质量。

平均 episode length 接近 200-step budget，也说明当前任务完成效率仍有限。

## 3. 旧 B0 Stage2：出现明显性能退化，已停止

### 3.1 Baseline 配置

该 Stage2 使用旧 clean50 Stage1 step12k frozen reference，而不是新 train450/10k。

Reference 的既有 matched development acceptance：

> **10/20（50%）**

Stage2 关键设置：

- H50/C50 native_macro；
- direct normalized actor；
- 4 training environments；
- learner batch 64；
- warmup 512 transitions；
- warmup / early learner 阶段包含约 2000 critic updates；
- critic : actor update ratio = 4 : 1；
- macro discount 当前固定 0.90，但尚未用真实 execution duration 严格校准。

### 3.2 性能变化

20-seed 周期评测显示：

- round 200 / 300：约 **45%**；
- round 800 / 900：约 **15%**。

训练因此在约 985 个外层 round 后主动停止。最近完整 checkpoint 为约 900 round。

外层 round 不等于 learner update 数；停止前记录的 learner update step 约为 8836。

最后阶段的典型优化指标约为：

- critic loss ≈ 0.0206；
- BC loss ≈ 0.00306。

这些 loss 较小 **不能证明 Q 值准确，也不能证明 actor 闭环安全**。当前唯一稳妥结论是：

> **在这套旧 reference + 当前 Stage2 配置下，在线训练后期相对 frozen reference 发生了显著性能退化。**

目前没有足够证据把根因唯一归结为：

- Q overestimation；
- reference 成功率不足；
- BC 太弱；
- reference dropout；
- actor action-space mapping；
- macro discount；
- replay distribution；
- 或其他单一因素。

## 4. Stage2 下一步：先诊断，不继续盲目加预算

下一轮优先级改为：

1. **BC-only / reference-consistency 检查**：确认在关闭或弱化 Q 驱动时，actor 是否能够保持 reference 行为；
2. **action deviation 统计**：跟踪 `a_actor - a_ref` 随训练如何增长，以及成功/失败之间的关系；
3. **reference dropout 消融**：确认 dropout 是否过早破坏 actor 对 reference 的 anchoring；
4. **BC/Q 比例检查**：评估 Q objective 是否压过 imitation / policy anchor；
5. **critic calibration / target audit**：不以 critic loss 低作为 Q 正确的证据；
6. **macro time / discount audit**：在真实执行时长明确后，再决定 `gamma_macro` 是否合理。

在这些诊断完成前，不继续使用原配置追加 online budget，也不进入 Physical Token B1/B2。
