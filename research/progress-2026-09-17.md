## 2. Hammer clean500 → clean490：全量数据审计完成

原 clean50 + 新增 450 条成功示范已经全部导出，共 500 条 raw/main/physics/video episode，episode 编号连续且 500 个 reset seed 唯一。

全量审计覆盖：

- 79,529 个原始帧；
- 318,116 张四相机 RGB；
- 79,529 个 MP4 帧；
- 所有 main / physics 数值字段的 finite / shape / temporal alignment；
- command / measured trajectory 连续性；
- state / action / physics transition 索引；
- repository physics validator。

未发现文件不可读、NaN/Inf、空白帧、图像尺寸异常、MP4 帧数不一致、字段长度不一致或 transition 错位。

### 2.1 10 条强轨迹异常

发现 10 条明显不适合作为标准动作监督的轨迹，主要表现为：

- 非初始阶段大幅 joint target branch jump；
- TCP / actual joint 同步异常运动；
- 个别 episode 存在异常初始绕转。

处理原则：

- 原始文件不删除、不覆盖；
- 从新 Stage1 train/eval candidate 中排除；
- 不把对应 reset seed 自动判成无效环境场景。

因此正式候选数据为 **clean490**。

### 2.2 10 条 contact / impulse 弱标签

另有 10 条轨迹动作连续性正常、抓取和末端几何可接受，但 sidecar 没有可靠的非零 contact / impulse 事件。

这类数据：

- 继续用于 Stage1 VLA/RLT 动作学习；
- contact / impulse 相关 auxiliary target 必须使用 validity mask；
- 不能把“未记录到冲量”直接当作“没有接触 / 任务失败”负样本；
- 其他可靠 measured-transition 字段可正常使用。

这成为后续 B1/B2 的正式数据合同：

> **trajectory validity 与 physics-label validity 分开管理；每类物理标签有独立有效性 mask。**

## 3. clean490 数据划分与 normalization

正式开发划分：

- `train450`：450 episodes，70,640 个训练时间索引；
- `eval40`：40 episodes，6,238 个开发验证索引；
- 总计 76,878 个 `T-1` transition index。

划分按 episode / seed 完成，不把相邻帧随机拆到 train/eval。

重要边界：

- eval40 是 **development validation set**，不是论文级 final test；
- norm stats 只使用 train450；
- eval40 和后续基于该 reference 的 Stage2 使用同一份 train450 norm；
- 旧 clean50 checkpoint 继续配旧 clean50 norm，不能混换统计文件做比较。

当前 imitation dataset 的 `state` 仍保持原有 command / drive-target 语义，并不自动等于后续 B1 所需的 measured qpos。未来 Physical Token measured-transition 必须显式读取真实 state / EEF / object consequence。

## 4. 新 clean490 Stage1：已正式启动

新的 baseline-recovery Stage1 从 generic π0.5 base 开始，继续采用论文/官方 topology 的 VLA + RLT 联合训练。

固定配置：

| 项目 | 当前配置 |
|---|---|

| Horizon | H50 |

### 运行快照

当前约：

> **3798 / 30000 steps（约 12.7%）**

这是运行中快照，不是实验结果。

首个真正有意义的下一门槛是：

> **5k checkpoint → 固定 eval40 H50/C50 闭环评测。**

后续按 `5k / 10k / 15k / 20k / 25k / 30k` 比较 success、completion time、failure stage 与 RLT representation quality；不按 train loss 最低直接选模型。

30k 是上限，不要求机械跑满。如果连续 checkpoint 的闭环能力无改善或明显下降，可以提前停止并选择 validation-best checkpoint。

当前 H50/C50 继续作为 Hammer 的 reference capability anchor；H50/C10 仍是单独的执行协议研究，不与 H50/C50 混合解释。

## 10. 对 Universal Physical Token 的直接影响

今天的进展进一步强化了三个实现约束。

### 10.1 Proposed action ≠ Executed action

Stage2 / B1 replay 必须保留 VLA proposal、实际 controller execution 与真实执行时长。

### 10.2 Command state ≠ Measured state

Hammer 当前 imitation state 仍是 command/drive-target；RoboDojo 中 arm joint 为 measured，而 gripper scalar 又是 command-derived。Physical Token 的输入和 target 必须按字段标注 provenance。

### 10.3 Physics labels 必须带 validity

clean500 审计已经证明 contact/impulse 标签并非总是可靠。未来 B2 不能把“label missing / weak”补成 0。

因此当前 Physical Token 数据契约继续固定为：

```text
reference / proposed action
actual executed action
command state
measured state
execution duration / executed length
reward / terminal
optional physics label + validity mask
```
