## 1. 今日结论

今天完成了两项对后续 Physical Token 实验非常关键的前置工作：

1. **旧 clean50 Stage1 的统一闭环能力曲线已经建立。** 在同一 20-seed 开发 cohort、相同 `H50/C50 native_macro`、固定 prompt 与 action-sampling seed 下，6k/8k/10k/12k checkpoint 的成功率分别为 40% / 35% / 40% / 50%。12k 是当前开发集上最高的 reference 候选，但曲线非单调、样本量仍小，不能宣布 Stage1 泛化问题已经解决。
2. **clean500 已完成全量质量审计，并收敛为 clean490。** 500 条原始成功示范完整导出；全量数值、四相机图像和视频解码检查未发现结构/对齐错误，但识别出 10 条不适合作为动作监督的轨迹异常。原始文件全部保留，正式候选数据改为 490 条。

这两项结果仍属于 **Gate 0 / data-quality strengthening**，不是 Physical Token 算法收益。

## 2. Stage1 6k / 8k / 10k / 12k：统一 20-seed 评测

四组评测均正常完成，使用完全一致的开发 cohort 与执行协议：

- `H=50, C=50`；
- RoboTwin `native_macro`；
- 固定训练任务指令；
- 固定 action-sampling seed；
- cohort 来自后续 clean500 数据中的一组新 reset seeds，与原 clean50 训练 seeds 不重叠。

| Stage1 checkpoint | success | rate |
|---|---:|---:|
| step 6k | 8 / 20 | 40% |
| step 8k | 7 / 20 | 35% |
| step 10k | 8 / 20 | 40% |
| step 12k | 10 / 20 | 50% |

### 当前解释

- 12k 是当前 **development candidate**，不是最终 reference；
- 曲线不是单调随训练步数上升；
- 20 个 seeds 不足以支持统计显著性或“训练越久越好”的结论；
- 12k 仍有 10/20 失败，因此不能说 Stage1 capability / generalization 已解决；
- 当前只保存了聚合成功数，尚不能分析具体哪些 seed 在不同 checkpoint 上改善或退化；
- 历史 8k 的 5/20 来自不同 prompt/noise 协议，只保留为历史记录，不与本轮 7/20 混算。

旧的 `base + alpha1` 长程 Stage1 run 最终停止在约 12.3k steps，因此 20k 目标没有完成。本轮 6k–12k 结果是对已有完整 checkpoint 的能力验收，不是 20k 最终验收。

### 12k 物理过程补录

已准备对同一 20-seed cohort 做 12k 完整物理过程录像与 chunk/physics trace 的入口，目的是定位抓取、保持、接触和敲击阶段的最早失败点。正式录像尚未启动；单环境补录的采样噪声可能与此前 20 环境批量评测不同，因此补录成功率需要单列，不能直接覆盖 10/20 的聚合结果。

## 3. clean500 全量审计：文件完整 ≠ 轨迹适合训练

500 条原始成功轨迹已经全部导出，episode 编号连续、seed 全部唯一。

全量审计覆盖：

- 500 条 main / physics / video / raw trajectory；
- 79,529 个原始帧；
- 318,116 张四相机 RGB；
- 79,529 个 MP4 帧；
- 全部图像 / 视频尺寸与帧数；
- 数值有限性、字段时间长度、state/action/physics transition 对齐；
- command / measured trajectory 连续性；
- physics sidecar repository validator。

没有发现：

- 文件不可读；
- NaN / Inf；
- 空白帧；
- 图像尺寸异常；
- MP4 帧数不一致；
- 字段长度不一致；
- transition 索引错位；
- 完全重复动作轨迹。

但 **自动导出成功不能等同于高质量动作示范**。

### 3.1 10 条强轨迹异常

全量连续性审计识别出 10 条明显异常动作轨迹，均来自新增数据。异常主要表现为：

- 非初始阶段出现大幅关节目标分支跳变；
- 实际关节 / TCP 同步出现异常运动；
- 个别轨迹存在异常的初始绕转 / wrap 行为。

这些轨迹虽然最终可能完成任务，但不适合作为“期望动作轨迹”监督。

**处理：**

- 原始文件不删除、不移动、不改写；
- 从新 Stage1 动作监督及 train/eval candidate 中排除；
- 对应 reset seed 不自动判定为无效场景，未来仍可单独用于环境评测。

排除后得到 **490 条候选合格轨迹**：原 clean50 全部通过，新采数据中 440 条通过。

### 3.2 10 条 contact / impulse 弱标签

另有 10 条轨迹在动作连续性、抓取和末端几何上可接受，但 sidecar 没有记录到可靠的非零 hammer-block impulse/contact 标签。

这里必须区分：

> **sidecar 的非零冲量型 contact 语义 ≠ 任务的全部几何接触 / 成功语义。**

因此这些轨迹：

- **保留用于 Stage1 VLA/RLT 动作学习**；
- contact/impulse-specific auxiliary target 必须加 validity mask；
- 不能作为可靠的“没有接触 / 任务失败”负样本；
- 其他可信 measured-transition 字段仍可正常使用。

这给后续 Physical Token B1/B2 一个直接工程约束：**每一类物理标签必须有独立 validity mask，缺失/弱标签不能填 0 当真值。**

## 4. clean490：正式开发数据划分

最新数据决策不再补采异常轨迹来强行凑 500 条干净样本，而是显式使用当前 490 条合格轨迹：

- **train450**：450 episodes，70,640 个训练时间索引；
- **eval40**：40 episodes，6,238 个开发验证索引；
- 总计 76,878 个 `T-1` transition index。

数据划分按 episode / seed 完成，不能把相邻帧随机拆到 train / eval。

### 重要边界

- eval40 全部来自新增数据，但其中包含部分此前已经用于开发评测的 seeds，因此它是 **development validation set**，不是论文级最终独立测试集；
- 最终论文级成功率 / checkpoint 结论需要额外封存的 independent reset seeds；
- norm stats **只使用 train450** 重新计算；
- eval40 与未来基于这套数据的 Stage2 共享 train450 norm；
- 旧 clean50 checkpoint 继续使用旧 clean50 norm，不能只替换 norm 后混合比较。

当前 Stage1 数据接口仍沿用 RoboTwin / OpenPI 既有的 command-state 语义；它不是后续 Physical Token B1 所要求的 actual measured qpos。B1 的 measured transition 必须从 sidecar / rollout measurement 显式读取实际状态，不能静默混用 command state 与 measured state。

## 5. 新 clean490 Stage1：CPU 准备已完成，GPU 训练尚未启动

新的 Stage1 baseline recovery 将重新从 generic `pi05_base` 开始联合训练 VLA task loss + RLT reconstruction：

- `rlt_alpha = 1`；
- `H = 50`；
- global batch 64；
- dual-GPU data parallel；
- default max = **30k optimizer steps**；
- warmup = 1k；
- checkpoint every **5k**；
- checkpoint 选择基于固定 eval40 闭环能力，不按最低 train loss。

CPU 侧已经完成：

- train450 / eval40 转换与映射检查；
- train-only norm provenance；
- 数值与图像抽样验证；
- OpenPI loader batch 检查；
- Hydra train / eval dry-run；
- RLT 模块相关回归测试。

**尚未启动新的 GPU 正式训练。**

30k 对 train450 的等效 frame-level 暴露约为 27 个 epoch 量级，与旧 clean50 在 20k steps 下约 162 个等效遍历不是同一过拟合风险水平。仍不能提前假设 30k 最优；若连续 checkpoint 闭环能力无改善或退化，应提前停止并选择 validation-best checkpoint。

## 6. 对 Gate 0 与 Physical Token 的影响

### Gate 0 的进展

现在可以确认：

- Stage1 并非完全失效，统一协议下已有 35%–50% 的开发成功率；
- H50/C50 是当前 RoboTwin native-macro reference 能力锚点；
- 12k 是当前旧 clean50 run 的开发候选，但尚未通过独立测试；
- clean500 已完成数据质量审计，下一轮 baseline 可使用更可靠的 clean490 数据；
- 数据质量和标签有效性已经从“工程细节”升级为 Physical Token 监督设计的一部分。

### 对 B1 / B2 的直接约束

B1 measured-transition grounding 必须区分：

```text
reference / proposed action
actual executed action
command state
measured state
```

B2 / contact-related auxiliary supervision 必须使用逐标签 validity mask。

当前数据审计已经证明：

> **不能把 contact=0 简单解释成没有物理接触，也不能把导出成功简单解释成高质量监督。**

这会作为后续 Physical Token 实现的硬数据合同。
