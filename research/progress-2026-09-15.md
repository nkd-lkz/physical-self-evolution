# 2026-09-15 · Hammer RLT Baseline Recovery

> 本页只记录公开、脱敏、已有证据支持的项目状态。原始路径、服务器账号、完整启动命令和私有监控标识不进入公开仓库。

## 1. 今日一句话状态

当前仍处于 **Universal Physical Token 的 Baseline / B0 前置恢复阶段**，还没有进入 B1 transition grounding 或 B2 physics grounding。

旧的 hammer RLT Stage1 `base-init + alpha=1 + 2k` 与旧 Stage2 已证明工程链路可运行，但尚不足以作为稳定能力基线。当前优先恢复一个可用、可配对评估的 Stage1 reference，再进入新的 Stage2 与 Physical Token 消融。

---

## 2. 两个需要严格分开的已知问题

### 2.1 执行协议差异：H50/C10 不是原生 RoboTwin reference 的公平能力锚点

Hammer Stage1 训练使用 `H=50` action horizon。RoboTwin 原生执行会将整段目标序列通过 TOPP 重定时为数量可变的物理步。

此前把 `H=50` 的预测只执行前 `C=10`，每 10 个目标重新进入一次 TOPP，会改变：

- 规划边界；
- 实际物理时间；
- 再观测频率；
- 后续状态分布。

因此：

- `H50/C10` 可作为历史工程诊断；
- `H50/C50` 作为当前 RoboTwin 原生能力锚点；
- 后续论文式 `C=10` 需要单独设计与验证，不能把已有 H50 checkpoint 直接改一个推理字段后当作等价复现。

### 2.2 训练预算差异：旧 Stage1 2k 明显弱于 standalone SFT20k，但原因尚未唯一归因

旧 Stage1：

- 从通用 `pi05_base` 初始化；
- `rlt_alpha=1`，联合训练 VLA task loss + RLT reconstruction；
- 2,000 optimizer steps；
- global batch 32。

Standalone task-SFT：

- 20,000 optimizer steps；
- global batch 64。

两者样本预算约相差 20×。现有离线动作误差检查还显示旧 Stage1 的动作 MAE 约高 4–5×。

但是，这些现象目前只能支持：

> **旧 Stage1 仍存在任务能力 / 泛化不足风险，值得做长程联合训练恢复。**

不能直接证明“训练步数不足”是唯一根因，因为还同时存在 batch、联合目标、采样随机性和任务难度等因素。

## 3. H50/C50 配对证据

当前固定协议下的开发诊断结果：

| 场景 | 旧 Stage1 2k | SFT20k | 解释 |
|---|---:|---:|---|
| fixed seed A | 0 | 0 | 两者都失败，不能区分方法 |
| fixed seed B | 0 | 1 | 同协议下出现 Stage1-specific capability gap |
| fixed seed C | 未完成 | 未完成 | 中断，不计入结果 |
| fixed seed D | 未开始 | 未开始 | 不计入结果 |
| 额外正对照 seed | 1 | 1 | 两者都能完成，证明 Stage1 并非完全失去任务能力 |

这组结果支持两个结论：

1. 旧 Stage1 checkpoint **不是完全不可用**；在至少一个有效场景中，H50/C50 原生协议能够成功。
2. 在至少一个严格配对场景中，SFT20k 成功而旧 Stage1 失败，说明恢复更强 Stage1 capability 是合理的下一步。

但样本数仍不足，不能把某一个 seed 的差异升级成总体成功率结论。

---

## 4. Reward / environment 的当前证据

官方 expert 在一个已验证场景中能够：

- 完成任务；
- 触发 native success；
- 沿 adapter 链路产生正 reward 与 terminated/success。

因此当前没有证据支持“reward 链路完全无法产生正样本”。

这不代表所有 reward timing、chunk discount 或 learner TD target 已完全验收；它只排除了一个最粗粒度的解释：**任务永远不给正奖励。**

## 5. 当前执行决策：长程 joint Stage1

当前优先实验固定为：

```text
pi05_base
  + rlt_alpha = 1
  + joint VLA task adaptation + RLT reconstruction
  + H = 50
  + 20,000 optimizer steps
  + 2-GPU data parallel
  + global batch = 64
  + micro batch = 2
  + gradient accumulation = 16 / rank
  + warmup = 1,000
  + checkpoint every 2,000 steps
```

配置 dry-run 已通过；正式 GPU 训练仍记为 **待启动 / 待验收**，不能提前写成完成。

20,000 × 64 对应 1,280,000 个样本槽位。相对当前约 7.9k transition 的 clean50 数据，这是高重复训练，因此存在后期过拟合风险。

因此 checkpoint 选择规则固定为：

> **不按最低训练 loss 选择；按固定 seed、H50/C50 闭环能力曲线选择。**

计划评测：`2k / 4k / ... / 20k`。

## 6. Stage2 的当前定位

旧 Stage2 C10 run 继续保留为：

- feature load；
- replay；
- actor/critic update；
- weight sync；
- checkpoint；
- timing / transition debugging

的工程证据。

但旧 run 依赖旧 Stage1，且训练 episode 没有获得正 reward，因此：

> **它不是当前 Physical Token B0 的性能基线。**

新的 Stage2 设计必须等新的 Stage1 checkpoint 通过固定 seed 闭环能力门槛后再启动。

---

## 7. 对 Universal Physical Token 主线的影响

领导定义的研究问题不变：

```text
Action-head compact readout
→ measured transition grounding
→ valid physics grounding
→ lightweight online adaptation
```

但实验顺序增加一个明确的 **Gate 0 — Baseline Recovery**：

```text
Gate 0A  恢复可用 Stage1 reference
       ↓
Gate 0B  固定 RoboTwin execution / timing semantics
       ↓
Gate 0C  建立可信 B0 online baseline
       ↓
B1      + measured transition loss
       ↓
B2      + valid physics loss
```

在 Gate 0 完成前，不实现大规模 Physical Token 消融，不把 Stage2 零成功解释成“缺 physics”。

---

## 8. 下一步验收顺序

1. 启动并完成新的 `base + alpha1 + 20k` Stage1 joint training。
2. 确认所有保存点数值有限、配置身份正确、无意外 resume / checkpoint 错配。
3. 对 `2k / 4k / ... / 20k` 做固定 action seed + environment seed 的 H50/C50 闭环评测。
4. 同协议保留 SFT20k reference 对照，并报告配对 success / completion time / failure stage。
5. 冻结一个有闭环能力证据的 Stage1 checkpoint。
6. 重新设计 Stage2：先建立公平 B0，再进入 B1/B2。

---

## 9. 当前不做

- 不因为旧 Stage2 success=0 就直接加入 physics loss；
- 不把 H50/C10 历史结果当作 Stage1 能力结论；
- 不用最低 train loss 选 Stage1 checkpoint；
- 不同时引入 Physical Token、Streaming RL、World Model；
- 不把单 seed 的 Stage1/SFT 差异写成总体显著性结果。
