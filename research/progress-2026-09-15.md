## 2. 旧 Stage1 的两个独立问题仍需分开解释

### 2.1 H/C 与 RoboTwin TOPP 执行协议

现有 hammer Stage1 action horizon 为 `H=50`。RoboTwin 原生 TOPP 会对整段目标序列重定时；历史上只执行前 `C=10`、然后重新查询策略，会改变：

- TOPP 规划边界；
- 实际物理时间；
- 再观测频率；
- 后续状态分布。

因此当前仍使用：

- `H50/C50`：已有 H50 Stage1 的原生闭环能力锚点；
- `H50/C10`：历史执行协议诊断，不作为 Stage1 能力公平锚点；
- 论文式 `C=10`：后续必须单独建立控制 / transition 语义，不能靠改一个推理字段宣称等价复现。

### 2.2 Stage1 capability / training budget

旧 Stage1：

- generic `pi05_base` 初始化；
- `rlt_alpha=1`；
- VLA task loss + RLT reconstruction 联合训练；
- 2,000 optimizer steps；
- global batch 32。

Standalone task-SFT：

- 20,000 optimizer steps；
- global batch 64。

已有离线动作 MAE 检查显示旧 Stage1 约高于 SFT20k 4–5×。这支持“旧 Stage1 存在 task capability / generalization 风险”，但不能把训练步数写成唯一根因，因为 batch、联合目标、采样随机性和任务难度也同时变化。

## 3. H50/C50 配对证据

当前开发配对结果：

| 场景 | 旧 Stage1 2k | SFT20k | 解释 |
|---|---:|---:|---|
| fixed seed A | 0 | 0 | 两者都失败，不能区分 |
| fixed seed B | 0 | 1 | 关键配对：存在 Stage1-specific capability gap |
| fixed seed C | 未完成 | 未完成 | 中断，不计入 |
| fixed seed D | 未开始 | 未开始 | 不计入 |
| 额外正对照 seed | 1 | 1 | 证明旧 Stage1 并非完全失去任务能力 |

因此当前最严谨的结论是：

1. 旧 Stage1 不是“完全失效”；
2. 但协议对齐以后仍出现 SFT20k 成功、旧 Stage1 失败的场景，恢复更强 Stage1 capability 是合理下一步；
3. 当前样本量不足，不能从单个 seed 推总体成功率，也不能把“训练不够”写成唯一原因。

```text

→ measured transition grounding
→ valid physics grounding
→ lightweight online adaptation
```

```text
Gate 0A  恢复可用 Stage1 reference
       ↓
Gate 0B  固定 execution / timing semantics
       ↓
Gate 0C  建立可信 B0 online baseline
       ↓
B1      + measured transition loss
       ↓
B2      + valid physics loss
```

clean500 属于 baseline/data quality reinforcement；RoboDojo 属于第二平台与外部有效性基础设施。二者都不能提前写成 Physical Token 方法结果。
