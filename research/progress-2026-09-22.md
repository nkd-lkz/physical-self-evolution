## 2. 可以形成的科研结论

**450 条示范训练的 Stage1 10k 模型在当前40回合开发评测中成功22次（55%），仍有18次失败。跨设备复测的聚合指标一致；目前尚不能证明优于旧 clean50/12k 的50%，也不能单凭 reference rollout 证明 RLT 表征收益。**

平均 episode length 接近上限，说明整组评测的预算消耗较高。进一步判断效率需分别统计成功/失败回合长度、超时数量和实际执行时长；仅凭总体均值不能断言所有成功回合都很慢，也不能把18次失败全记成 timeout。

## 3. 与现有记录的关系

既有记录将该实验归于 Hammer/RoboTwin 的 train450/eval40 路线，并记录 H50/C50 native_macro、固定 prompt/action seed、train450 normalization。**这些是既有仓库上下文，本截图没有重新展示完整配置。** 原始 run 对齐前，不将其标为本轮独立重新核验的配置。

当前统计规则：

- 保留已有两次设备运行的记录；本次截图不默认增加第三次运行。
- 同一 cohort 重复评测不合并为80个独立 seed，更不因再次入库继续增加样本量。
- 聚合一致可能对应不同的逐 seed 成败组合，必须逐回合核对才能升级为逐 seed 一致。
- 新 eval40 与旧 clean50/12k 的20回合 cohort 不同，55%与50%不构成受控改进证据。
- Stage1 包含联合训练；缺少匹配训练数据、更新量与执行协议的消融，无法单独归因于示范数量或 RLT representation。

## 4. 下一步最小核验（待执行）

1. **对齐来源与配置。** 保存两次 run 的标识、checkpoint/norm/config 版本、environment seed、action seed及评测日期；确认本截图对应已有复测还是另一轮同协议运行。公开记录只保留脱敏版本信息。
2. **逐 seed 核对。** 比较40条 success、return、episode length、termination reason。区分“聚合相同”“逐 seed成败相同”和“轨迹数值相同”三个层级。
3. **复盘18个失败。** 根据日志与视频标注阶段和现象；timeout、失抓、接触失败等类别以实际证据为准。单列成功回合完成时长，判断预算瓶颈。
4. **准备匹配比较。** 5k、10k与旧12k使用同一开发 cohort、prompt、动作采样seed、控制器与执行协议；按各checkpoint正确配套norm并记录差异。若要隔离训练规模或表征效应，还需匹配其他训练因素，不能仅换评测seed就完成归因。
5. **确认视频证据。** 核对本地文件是否存在、可播放以及回合对应关系；是否上传W&B是另一项状态，不能由“0 media”推断无本地视频。

新模型的当前定位仍为 development reference candidate。最终能力判断需独立封存测试；RLT/Physical Token收益需另行受控实验。
