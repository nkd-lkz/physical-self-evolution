# 物理经验能否减少干预：可证伪的研究合同

> 2026-09-22 讨论整理，全部为待验证假设与实验设计。没有新增 Physical Token、干预或在线学习结果。<br>
> 关联：[机制与100/200步解释](https://nkd-lkz.github.io/physical-self-evolution/reader.html?path=research/rlt-intervention-2026-09-22.md) · [恢复与小算力入口](https://nkd-lkz.github.io/physical-self-evolution/reader.html?path=research/migration-recovery-2026-09-22.md)

## 1. 保留研究愿景，收紧首轮问题

“从交互沉淀物理经验，提前预判后果，在保持成功率与吞吐率时减少干预、更快训练，并适配多任务”是合理的长期目标，但同时混合了表示、预测、门控、控制、学习效率和泛化六类主张。首轮应选一个主问题，其余作为约束或后续验证。

**主问题 A：固定 base、专家、阶段切换、干预规则和 learner，在匹配数据与资源预算下，action-conditioned measured-consequence grounding 能否降低达到预设无专家成功率目标所需的累计专家控制时间？**

这要求先有可信干预闭环和小预算 learner。算力暂不支持时，先用冻结特征的离线后果 probe 检查机制；probe 通过仅是继续实验的依据，不能回答“训练更快”。RLT 保留为可选 downstream baseline，不要求先跑通大规模 RLT 才能做表示研究。

**独立问题 B：固定策略与专家，在相同专家预算下，预测后果的 gate 能否比停滞规则或普通风险 gate 更早识别需要帮助的状态，并提高辅助成功率？**

先做 A 的机制和固定门控对照，再单独做 B。首轮同时改变 representation、专家、gate、chunk 和奖励，会失去归因。未来再用 representation × gate 的因子设计检查交互效应。

## 2. 对“原 RLT 只是语义监督”的修正

这个描述过强。RLinf 的原 RLT 从 VLA prefix hidden states 提取并重构紧凑表示；这些特征可能已包含几何、动作和物理相关信息，Stage2 的 critic 也使用真实任务反馈。因此不能预设其“没有物理”。[官方表示说明](https://rlinf.readthedocs.io/zh-cn/latest/rst_source/examples/embodied/rlt.html#rlt)

本项目更准确的增量是：从保持 VLA 内部特征，扩展到**显式的、以动作和真实时长为条件的执行后果监督**，再测试有效物理约束是否有额外收益。当前迁移的 RLT prefix readout 不能改名为 action-head token；action-head tap 需要实现和匹配对照。是否值得用 action-side 特征，本身就是需要证伪的假设。

## 3. “沉淀经验”具体存什么、更新什么？

第一版经验单元是一段可追溯 transition：当前可部署历史、候选/实际命令、实际执行前缀和时长、未来实测结果、标签有效性、控制者、干预请求/执行以及终止原因。它不是仅靠语言总结的“物理规律”。

离线 grounding 阶段在冻结 action model 的条件下训练小 readout/decoder；正式在线 actor–critic 比较默认冻结 readout，保持表示合同一致。若后续让小 dynamics decoder 在线适应，应另列实验，并固定/版本化 replay 特征；不能把新旧 token cache 无标识混合。经验只有改善预测、决策或适应才形成研究证据。

## 4. 多层级信号不等于第一天就造多个 token

| 层级 | 可考虑的信号 | 标签与部署边界 |
|---|---|---|
| 运动/执行 | measured Δq、末端运动、命令跟踪偏差、实际时长 | 不能把 drive target 当 measured state；统一坐标与单位 |
| 交互事件 | 相对运动、稳定抓持、滑移、接触、停滞 | 只用有效标签；缺失冲量不填0作为“无接触” |
| 任务后果 | 进展、失败风险、剩余时间、条件可恢复性 | 依赖任务目标与剩余预算；特权标签不直接进入部署输入 |

先用一个 compact latent 配不同预测头与 validity masks，逐项消融信号，再决定是否需要分层表示。多任务可以共享相对坐标、时间与动作接口、损失形式和小型 task adapter；成功定义、传感器和动作语义仍需对齐。

第一轮 physics loss 优先约束**预测量**的 FK 一致性、关节/速度/执行范围等。只对已测真值算一个常数 residual，不会给表示提供有效梯度；盲目平滑接触过程可能抹掉冲击。没有可靠力、标定和接触模型时，不宣称学习了摩擦定律或刚体动力学。

## 5. 从低成本机制检查走向正式对照

### 5.1 离线 probe：先回答表征有没有新增信息

恢复约20–30条有成功、有失败的交互作为 pilot，一次性用冻结模型导出少量特征，缓存后用线性模型/小 MLP 拟合。所有组共享历史、候选动作、时间条件、标签、训练划分与容量：

| 对照 | 输入/监督变化 | 用途 |
|---|---|---|
| 简单预测器 | 零变化 / 简单运动预测 | 排除大量静止帧带来的虚高分数 |
| State + history + action | 不使用 VLA latent | 排除只是加了状态或历史的收益 |
| Original RLT / backbone | 增加 prefix/RLT 特征 | 现有表示基线 |
| Head readout | 同容量 action-head 特征 | 隔离 readout 位置 |
| Head + consequence | 增加 measured outcome grounding | 检验后果监督增益 |
| Head + consequence + physics | 再增加有效约束 | 后续独立消融，非首轮必需 |

按 episode/物理条件切分，禁止把相邻帧随机分到训练与测试；norm 只用训练集。Diffusion/flow tap 固定层、采样时刻及 noise convention，不能以未来示范动作 teacher forcing 产生部署输入。辅助预测误差、PR-AUC和校准应分阶段、分有效标签报告。

小数据只用于判断是否有信号。如果 head readout 在匹配后始终不优于 state/history 或 prefix，就应收缩或否定 action-side 优势，而不是继续增加模块掩盖失败。

### 5.2 正式学习比较：表示和干预基础设施分别验收

| 组 | 固定内容 | 唯一主要变化 |
|---|---|---|
| B0-RLT | base、专家、gate、动作时间语义、learner、预算 | 原 RLT 表示 |
| B0-Head | 同上及 readout 容量 | action-head tap，无物理 grounding |
| B1 | 同 B0-Head | measured consequence supervision |
| B2 | 同 B1 | valid physics constraints |

先在同一固定数据包上做机制比较；在线阶段匹配交互/专家/计算预算与种子，而不是要求不同策略产生完全相同数据。专家 checkpoint/脚本版本与触发、归还条件必须一致。

补充必须保留的系统基线：reference-only、expert-only、相同纠正数据与资源下的 BC/DAgger 类方法。若新增恢复数据，按[09-21的表示×恢复数据设计](https://nkd-lkz.github.io/physical-self-evolution/reader.html?path=research/xpace-jev-rlt-ideas.md)分离“数据更好”和“表征更好”，不要把两者合并归因。

### 5.3 Gate 研究：之后单独做

冻结被控策略和专家，比较停滞规则、风险/不确定性基线、带物理后果预测的 gate。在开发集调节阈值以匹配专家预算，在留出集固定阈值报告实际预算消耗；不要使用测试结果重新调阈值。保留相同的归还控制条件、切换延迟和最小持续时间。

已有 [ThriftyDAgger](https://arxiv.org/abs/2109.08273) 与 [LazyDAgger](https://arxiv.org/abs/2104.00053)覆盖风险、新颖性和切换负担。后果预测必须超过这些普通门控思想在相同输入下的作用，才能支撑新的表示贡献。

## 6. 指标：避免“干预次数更少”的假象

| 指标 | 统计定义 / 要求 |
|---|---|
| 无专家成功率 | 固定 base→actor 阶段协议、禁止 expert；不简称为纯 actor 成功率 |
| 辅助成功率 | 同等初态与预算，允许指定 expert；单独报告 |
| 发生干预的回合比例 | 至少一次实际 expert 控制的回合 / 全部回合 |
| 干预事件数 | 非 expert→expert 的切换次数；请求和实际执行分别计数 |
| 专家控制时长 | 实际 expert 执行的模拟/机器人秒数；另计推理和墙钟耗时 |
| 专家动作占比 | expert 的实际动作/时长分母明确，不只给 `human_mask_ratio` |
| 恢复成功率 | 被接管状态在规定预算内完成的比例，并分失败类型 |
| 吞吐率 | 每单位墙钟时间成功完成数，注明是否包含推理、规划、重置 |
| 训练效率 | 达到预设目标所需交互、learner updates、墙钟和累计专家时间分别报告 |
| 提前预判 | 决策前预测的 PR-AUC、校准、误报和提前量；报告事件基率 |

一次接管持续到回合结束可能只有1个事件，却耗费大量专家时间；放宽门槛可以减少请求，却牺牲成功率。因此首要成本建议用专家控制时长，事件数为补充。仿真模型/脚本专家的控制时长不是实测人类工时。

“保持成功率和吞吐率”需在实验前设定有实际意义的非劣界限、样本量与不确定性报告。训练达到目标的定义、评测频率和停止条件也应预先固定；预算内未达标记为未达到/截尾，不把最后一步当作达标时间。专家预训练、恢复数据生成、离线 grounding 和缓存导出成本同时报告。

Pilot 的4–8个或几十个回合不足以证明小幅提升、非劣或多任务泛化。正式学习曲线需区分训练随机种子与评测 episode 种子；共同初态做配对，置信区间按独立回合/训练运行处理。

## 7. 风险、需要帮助与可恢复性不同

“学生可能失败”不等于“专家现在接管就能救”。可恢复性必须条件化于历史、目标、专家/控制器、剩余时间与允许的动作：

```text
recoverability = P(在预算 B 内完成 | history, goal, expert, controller, B)
```

“是否干预”的理想依据是预期专家收益与成本，而非单看风险。然而同状态下学生继续与专家接管的两个结果通常不能同时观察。

专家接管以后，观测到的是专家动作的后果；学生未执行的动作不能直接标为失败。要做反事实比较，需要恢复包括物体、速度、约束/接触、控制器与 RNG 的完整状态，或验证过的前缀重放，再分支执行并计入全部采样成本。只复制 robot qpos 不够。没有可靠分支能力时，只报告已执行动作的预测与实际辅助效果。

## 8. 适合当前机器的顺序与停止条件

1. **恢复冻结 reference。** 先单观测、单 seed，再4–8个串行开发回合；不续训大 VLA。
2. **验收最小干预。** 一个 Hammer 失败类型、一个专家、固定触发与归还规则，确认接管真的发生且从当前状态能恢复。
3. **缓存特征 probe。** 约20–30条成功/失败交互，先预测 measured motion/relative motion；仅在有效时加入事件标签。
4. **单因素物理变化。** 例如一个摩擦或质量参数的3档、每档4–8个配对回合；这是建议 pilot 预算，不是功效分析或结果。
5. **小 learner 与正式合同。** BC/reference consistency、Q与时长语义可信后，固定 gate 比较 B0/B1；再考虑 B2和 learned gate。
6. **迁移验证。** 先留出物理条件，再第二任务，之后才扩大模型/本体。不能由 Hammer 一个任务宣称通用规律。

原09-21提出的多任务×多种子大矩阵保留为后续扩展，不作为当前恢复阶段的最低要求。若缺旧权重、专家不能恢复、标签不可靠或 probe 无增量，应在对应层停止扩大预算并记录负结果。

当前可对外使用的研究表述：**研究从真实交互后果中获得的紧凑物理表征，能否在固定专家和资源约束下提高后果预测与局部适应效率，并减少维持任务能力所需的干预。跨任务与物理规律迁移仍为待验证主张。**
