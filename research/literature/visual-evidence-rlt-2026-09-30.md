# 从注意力可视化到交互证据：RLT 新方向评估

这份记录评估“关键操作时应该看哪里”是否值得成为独立 RLT 探索，并记录三条现有分支的追加实验。结论是值得做低成本诊断，但“让注意力集中到目标区域”已有直接近邻，不能单独作为创新主张。本轮已修改、测试 FLARE／Zeva／Jev 的诊断代码；视觉分支仍是方案，尚未建立新 worktree、提取当前模型热力图或启动注意力训练。

## 先确定失误来自哪个环节

部署失误不应直接归因于注意力。需要分别检查训练与部署观测差异、相机与控制标定、action chunk 执行期间的反馈延迟、视觉无法确定的接触状态，以及 VLA 表征压缩后是否丢失精细几何信息。最后两项尤其不能靠“热图更红”确认或解决。

对于当前插入任务，应观察夹爪、木块前端和孔口之间的关系，而不是只框住木块。遮挡发生时可能需要另一视角或扩大视野；将全部背景权重设零也可能删去障碍物、支撑面和空间参照。以上是待诊断的机制假设，不是当前失败轨迹的已确认根因。

## 最接近的公开工作

以下均核对论文原文，未复现其结果；不同模型、机器人和任务的成功率不与本项目横向相减。

| 工作 | 可以借鉴什么 | 与当前问题的边界 |
| --- | --- | --- |
| [ActGaze，2026-09-24](https://arxiv.org/html/2609.28955v1) | 在已具备动作能力的 π0.5 上抑制局部视觉证据，以动作目标误差增量训练 gaze head，再训练 action attention 对齐 | 最直接近邻。依赖示范动作目标，是训练方法，不是仅加一个推理 hook；没有额外 gaze 标签不等于没有监督 |
| [VLA-Trace，2026，v2](https://arxiv.org/html/2605.30117v2) | 联合分析表征、attention 路径与输入干预；包含 π0.5 和 OpenVLA | 适合诊断工具设计；局部视觉关注与指令遵循可能脱节，不能把一张热图当成完整解释 |
| [DTP，2026](https://arxiv.org/html/2601.16065v1) | 结合指令相关性与动作 attention，筛除干扰视觉 token | 推理期干预参考，不能假设对当前 OpenPI 路径开箱即用；筛选和重新推理需要计入耗时 |
| [IGAR，2026](https://arxiv.org/html/2603.06001v1) | 无额外训练的 attention 重校准，恢复语言 grounding | 主要研究指令与视觉证据冲突，并非专为局部插孔几何精度设计 |
| [ReconVLA，2025](https://arxiv.org/html/2508.10333v1) | 用 gaze 区域重建辅助目标形成隐式 grounding | 训练期辅助监督近邻，不证明本项目只需新增一个 loss 就会改善控制 |

一般 VLM 中的 [Attention Faithfulness，2026-09-01](https://arxiv.org/abs/2609.00830) 也提醒：不同样本的 attention 忠实性并不一致。这不是机器人实验，但支持把热图视为诊断线索，而非因果证明。

## 当前代码中需要分开的两条路径

当前 RLT 不存在一个覆盖所有动作来源的统一 attention 图。冻结 VLA 生成参考动作，小 actor 则根据 RL token、本体状态和参考动作产生关键阶段动作，两者必须分开标注。

1. **VLA action → image**：`pi0.py::run_prefix/run_suffix` 构建视觉／语言前缀与动作后缀；`modules/gemma.py::Attention.forward` 内部 softmax 后的权重可用于诊断 action query 对各相机 image token 的读取。Flow Matching 多次去噪需要记录层、query 和去噪步，不能随意平均后称为唯一解释。
2. **RL token → prefix image token**：`rlt_token_transformer.py` 读取最后一个 learned token；其 attention 调用目前不返回权重。即使提取这些权重，它们指向的前缀特征也已经经过上下文混合，不能等同于原始像素的重要性。
3. **实际小 actor 的动作依赖**：Stage 2 MLP 没有自己的图像 patch attention。要解释它，应保持噪声、状态和其他输入相同，干预图像后重新提取 RL token，再比较实际执行动作；只展示冻结 VLA 热图会混淆两条路径。

可视化应按实际 token 布局映射相机与 patch，排除 padding，不硬编码网格尺寸。默认 `rlt_use_mask=False` 是现有 checkpoint 合同的一部分，不能为了画图静默改变计算行为。采样少量层／帧／query，脱离计算图后保存；先验证关闭和开启采集时动作一致，再测额外显存和延迟。

## 建议的新切入口：经验指导视觉证据选择

与其研究“让热图更集中”，更贴近长期目标的问题是：**机器人能否根据过去已经完成的交互，判断当前视觉证据是否足够，并为下一次控制选择需要补充的局部信息？** 这只是候选研究贡献，仍需与 ActGaze、历史条件视觉选择和 UniMPA 等近邻进一步对照。

第一版保持现有 Stage 1、全局 RL token 和参考动作不变，增加一个可关闭的局部证据读取器。读取器根据当前图像中的夹爪／物体／目标关系生成少量局部 token，与全局特征一起输入小 actor／critic。局部区域来源必须记录：RGB 检测／跟踪属于部署可用输入；人工点选属于额外人工信息；模拟器真值只作标注或单列 oracle 上界，不能混进主要对照。

```text
当前 RGB、指令、本体状态 → 冻结 VLA → 原有全局 RL token、参考动作 ─┐
当前 RGB + 已完成交互 ───→ 局部证据选择／读取 → 少量局部 token ──┤
                                                               ↓
                                                     actor / critic → 执行
                                                               ↓
                                       新观察与真实结果 → 更新下一次可用经验
```

图中局部分支和经验驱动选择均未实现。第一阶段只诊断，不修改动作；第二阶段比较固定局部区域与随机等面积区域；第三阶段才考虑经验条件选择。三个已有分支是可分别借鉴的机制，不应一次全部合并：FLARE 提供后果预测误差，Zeva 提供历史有效性判断，Jev 提供有限候选决策。每次只引入一个变量，避免收益来源无法解释。

若训练局部读取器，VLA 和既有 RL token 初期保持冻结，只更新新增模块及声明允许更新的 actor／critic；TD 或后果监督均使用真实执行后的反馈。若之后允许视觉底座更新，应作为另一个实验条件并单独计入训练成本。推理期前向重加权、在线参数更新和只画热图是三件不同的事。

## 用什么证据决定继续或停止

首先取同一权重下的成功与失败轨迹，固定 action sampling noise、相机、初始状态和 task，分别观察 VLA 与 RL actor 接管时段。对高关注区、人工确认关键区和随机等面积区做模糊／遮挡，比较动作变化。有正确示范动作时再比较动作误差增量；没有标签时，动作变化仅说明敏感性，不说明变好或变坏。

随后比较原始 RLT、只开采集、随机等面积局部输入、固定关键局部输入、动态关键局部输入。控制输入分辨率、参数量、推理预算、奖励、expert 与接管规则。多次查看过的开发场景不再冒充最终密封测试；至少 20 个配对初始状态用于初筛，正式结论需要独立场景和更多重复。

主指标是闭环成功率、插入误差、人工接管次数／时长、异常接触和端到端延迟；ROI attention 比例与热图熵只作辅助指标。若热图集中却控制不变，停止“注意力即瓶颈”的主张。若局部裁剪导致遮挡或漏掉障碍，需要回退全局视野。没有真机交互、独立迁移与跨次经验收益，就不宣称真机自进化。

这轮先用 CPU 排查机制限制，没有挤占 GPU 2，也没有干扰 GPU 0/1。

| 分支 | 新增代码与实验 | 当前结论 |
| --- | --- | --- |
| FLARE | 已执行手臂前缀均值化，保持命令总量、夹爪和未来后缀；同时测输入与预测 RMS | 一份 1000-update residual checkpoint 的 12 条既有开发轨迹上，h=10 原始误差 0.22646、均值化 0.22874、倒序 0.22744。对顺序变化较弱，不能把 action sensitivity 等同于时序物理规律 |
| Zeva | 有权重历史读取；6 seeds × 3 合成响应条件 × 5 遗忘规则；预测发生在写入当前结果之前 | 自适应清理在响应减弱后前 8 步 MSE 从 6.96e-4 降到 3.34e-4，稳定条件不变；是看过固定遗忘结果后的探索，尚无接触／真机验证 |
