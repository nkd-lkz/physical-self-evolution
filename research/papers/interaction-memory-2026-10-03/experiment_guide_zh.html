RLT 交互记忆研究的实验执行指南

这份指南把英文论文中的假设转换成当前 Zeva 分支可以依次完成的开发与实验任务。先验收仿真 baseline；通过后在一个分支完成“正确的记忆输入—可学习的经验表征—匹配预算的控制收益—冻结参数后的经验收益”闭环，再扩展迁移和真机。当前最该补的是证据与训练目标，不是更大的网络。

日期：2026 年 10 月 3 日。目标：CVPR 2027。 这是研究执行计划；下文明确区分当前可执行命令、需要开发的能力与已观察结果。本次只编写和验证材料，没有启动新训练。两组 baseline／attention 只读预检均通过；它们检查路径和配置，不代表本次运行过 GPU rollout。

10 月 3 日发布修订：先验收仿真 baseline，再开发 Stage 1B 与新记忆模块。AlphaBrain／LIBERO 目前仅完成源码和公开结果核查，尚未在本项目运行。下面第 4、11、13 节已按这一先后关系调整，方法和现有开发数据的证据边界不变。

1. 先把研究主张定准确

建议论文主线为：

冻结 VLA 提供当前场景与任务的表征；已经完成的动作及其真实后果提供执行条件的证据。我们学习如何把这种证据压缩为可检索、可更新的条件表征，供 RLT 的小 actor／critic 使用，并检验它是否降低在线交互成本、支持参数冻结后的适应，以及能否在相容的新条件中复用。

这里有三层“经验”，不能混写。replay 中的 transition 通过 RL 更新权重，是 baseline 已有的学习机制；运行时 memory 改变下一次决策的输入，是要单独验证的无梯度适应；跨任务复用 source bank 才涉及记录层面的迁移。权重迁移与记忆迁移必须分别做对照。

“物理规律”暂时用操作性定义：表征包含对后续命令响应有预测价值的信息。它可以隐式表达执行条件，但不直接等于摩擦系数、刚度、接触力，更不能仅凭预测误差称为因果辨识。机器人不动可能是接触，也可能是饱和、限位或控制器响应不足。

投稿主张只保留实验能支持的部分。若最终只有 q-only 响应统计有效，就需要缩小“视觉交互表征”的表述；若 memory 只改善预测、不改善控制，就不能继续写“加速 RL 收敛”。

3. 最小方法：让历史表征为未来结果提供信息

训练样本严格按时间构造：过去记录 → 当前条件 c_t → 当前实际执行动作 → 后续 Δq／z。c_t 中只能包含已经完成的旧事件。预测头可以读取训练目标对应的动作，但不能读取其结果；这条动作完成后才能写入下一个 memory。

第一版采用 64 维 event/context，128 隐藏维、两层轻量时序编码器、4 个 attention heads。保留动作顺序与 valid mask；先做 q 变化 Huber loss 和后继 z 的 cosine loss。选择直接预测作为初始 latent head，保留 residual 对照。权重从 lambda_q=1、lambda_z∈{0,0.1,1} 开始，按训练集标准化，并只用 validation 选配置。它们是起始设定，不是已有最优参数。Zeva 已有前／后交互后果预测，因此这一 loss 属于借鉴；reader 训练接到 RLT 上是否形成足够的新贡献，仍取决于直接近邻对照和新的实证发现，不能由叙事保证。

不能只让 encoder 重建自己输入的 Δq。那样只证明会压缩记录，不证明对下一步有用。训练目标必须是后续、互不重叠的 chunk；同一 trajectory／pair 的所有窗口进入同一 split。norm、候选 bank、统计阈值均不得接触测试数据。

先用固定 horizon 的有效非跨 reset 窗口建立预测诊断。完整 terminal transition 仍可用于 RL；预测数据若排除了 terminal，需要单独报告筛选比例与终止附近误差。不能把“已经成功所以提前结束”的长度或 success flag 作为免费未来提示。用于线上 residual 检测时，必须在执行前固定预测 horizon，并明确反馈对应哪一次预测。

Stage 1B 先离线学 encoder／reader／decoder，Stage 2 初版冻结前两者，只训练 actor／critic，保留全部 baseline 参数。这样可以检查“已有可用经验坐标是否帮助 RL”。之后再比较 TD＋辅助预测在线更新 reader；若更新，则旧 replay 保留原始快照并重新编码，缓存 key 需要版本控制。

失败数据进入两条路径：真实后果训练 predictor；真实 reward 与 successor 训练 critic。不要把失败动作自动加入正向 BC。奖励用于任务价值，不默认写进可迁移的物理 event。接触标签若取自 simulator，只能是明确标注的 privileged auxiliary supervision，测试 policy 不得读取。

Stage 1B 的最小数据与 checkpoint contract

拟新增缓存每行包含 trajectory_id, chunk_id, start_z, next_z, start_q[9], next_q[9], executed_actions[10,8], valid_ticks[10], true_terminal, truncation, controller_schema_id。视觉 z 的实际维度从固定 Stage 1 checkpoint 读取，不在数据脚本另写一份常数。raw q 必须来自执行环境，不能从归一化 proprio 反推而不核对 transform。source task 和隐藏 physics 标签只用于 split／分析，与模型输入字段分开保存。

样本 builder 先按完整 trajectory/pair 划分 train／validation／test，再在各自 split 内构造“前四条＋旧 archive”的快照。训练时重建 past-only bank；测试 source bank 仅来自训练源任务。缓存需要 Stage 1 权重 hash、controller 单位、action scale、simulator revision、训练集 normalizer 与 schema version。若 successor 是 reset 后状态，丢弃预测样本并修复 collector；不能把它当随机噪声继续训练。

拟新增的 Stage 1B trainer 只载入缓存，训练 event encoder、reader 和预测头，导出包含架构参数、normalizer、schema version、Stage 1 hash、weights 和 validation 选择依据的 checkpoint。Stage 2 严格核验这些字段。第一版 decoder 不参与 actor 推理；需要 residual 监测时另测其时延。测试覆盖 future-record 排除、paired split、空记忆、terminal/padding、checkpoint 不匹配拒绝和冻结参数边界。模块名与 CLI 需开发后再确定，本文没有把未实现脚本当可执行入口。

4. 先完成 baseline 验收

以下是执行顺序与验收条件，不是已经完成的实验，也不承诺固定小时数内收敛。暂缓新增 Stage 1B、action-expert 约束和多种记忆网络。

阶段执行内容通过条件两张卡如何使用
A：公开模型复评固定 AlphaBrain 604924b，加载配套 Qwen VLA 与 RLT_a 发布权重；先 task 0／3／6 各 20 回合，再完整 10×50 回合。相同初始状态与动作协议；保存逐回合记录。小样本不能直接比较公开整体 92%。GPU 0：VLA-only；GPU 1：发布模型。先从少量环境 worker 测资源。
B：重新训练两阶段优先尝试同仓库 full-token RLT 与已验收的 Qwen VLA。显式提供 Stage 1 demonstration 配置；随后训练 Stage 2。BC warmup 保持基本能力；实际采样和更新计数正常；保存／恢复后的动作与评估一致。先一个 seed 排查，再并行不同 seed；环境数量由实测吞吐和内存决定。
C：确认 baseline至少 3 个训练 seed，在有成功样本且未饱和的任务上对比初始 VLA。同时记录无辅助成功率、环境 step、有效 chunk、wall-clock 和成功轨迹数；报告波动及负结果。同一实现、同一训练预算。正式关键对照再扩到 5 个 seed。
D：交互记忆对照仅在 baseline 通过后，比较 none／recent／attention／response，再开发 consequence reader。统一初始化、routing、数据和交互预算；后续独立测试 retain／clear 与条件变化。两张卡跑匹配组或不同 seed，不同时更换多个模块。

RLT_a 的公开 92% 与 full-token RLT 不是同一方法；前者用于验收仿真链路，后者仍需独立重训。若必须保持 π0.5，需要先确认配套 checkpoint 与数据，不能把 Qwen 结果当 π0.5 复现。Stage 2 不要求 VR，仿真可提供奖励；没有纠正数据时仍需确认初始 VLA 能采到成功轨迹。

原 ManiSkill 路线保留作为历史证据与候选实现。其 12 小时 memory run、关键阶段 baseline 和短 smoke 采用不同控制与预算，不能直接比较。原先建议的 2,000 chunks 只是 pilot 预算示例，正式预算应由实测吞吐和 baseline 学习曲线确定。

5. 先补的工程约束

  1. 实验矩阵能真实切换。 response 无可训练 memory 参数，不能沿用 audit_adapter --prefix memory_encoder. --require-change 的成功条件；它应验证 actor／critic 更新、响应特征正确、无意外参数，而非要求固定读取器变化。模型 shape 改变时不能直接续训旧 Stage 2 ckpt。
  2. replay 恢复覆盖 cache eviction。 小到没有淘汰的 resume smoke 不够。保存文件、index、sample count、trajectory counter 与分 rank 恢复需要一致；恢复后再次 append／sample 也要正确。现有 runtime memory 不自动随 Ray 环境恢复，应明确 reset，不声称 bitwise mid-episode resume。
  3. 执行与时序一致。 改动 joint memory 时验证被 routing 选中的动作、提前 terminal、真正 terminal successor、partial reset、owned snapshot、NaN padding 和 all-empty attention。测试应放现有对应 component 文件，不按 bug 新建一堆文件。
  4. 单位明确。 pd_joint_delta_pos 归一化 command 与 rad 不可直接相减；当前 response arm scale 为 0.1，必须核对实际 controller。视觉 latent 与经过 transform 的 proprio 也不能当原始物理量。旧预测诊断把旋转臂关节与直线手指坐标一起平均，不能把整体 MSE 解释成 rad²；新实验应分别报告 arm／finger 误差及训练集标准化后的聚合误差。
  5. 证据输入可部署。 隐藏 stiffness/friction、真实接触标签、task success、oracle phase 不能悄悄进入物理 context。若 baseline 原有 phase gate 用 simulator state，单列披露并所有组保持一致。

变更应在同一个 research/rlt-zeva-interaction-memory 研究分支连续完成，以固定 revision 划分实验，不再并行扩大 FLARE／VR 支线。远程 abb43823 与本地 f2d1cf64 的差异先单独查看；本次没有合并。

6. 两张卡上的正式矩阵与停止条件

优先级不是一次跑完所有方法。 先确认一个插入任务，再扩展到三个任务家族；更窄孔洞只能算同任务几何条件。

阶段 对比 种子／评估 开始下一阶段的依据
P0：工程 baseline、attention、response 的短跑及恢复 每组 1 次，固定边界测试 配置、动作、计数、梯度与保存正确
P1：表征 current-only、recent、archive、response、consequence；补 no-action／shuffle 3 个初始化；按 trajectory group 统计 新 held-out pair 上有可重复的有效信息读取
P2：闭环 original RLT、capacity control、recent、attention、response、consequence 首轮 3 个训练种子；每轮 validation 20 回合；正式测试另留 consequence 在相同预算下有值得确认的控制信号
P3：机制 固定参数下 retain／clear／shuffle；5 次尝试 配对 100 个实例起步；多训练 seed 每次尝试的收益不能仅由多次抽样解释
P4：扩展 三任务家族；eRLT-style、prediction-only；必要消融 核心差异争取 5 seeds；次级不少于 3 AUC、最终成功、wall-clock 结论相容
P5：迁移／突变 related／unrelated／empty source bank；旧条件切换 单独保留未见物理值和任务实例 量化负迁移、恢复和稳定场景代价

P1 的 no-action 消融必须同时去掉 history event 中命令信息与 predictor 当前动作输入，另补“只去掉其中一处”的定位对照；仅将当前动作置零、保留历史动作，会回答不同问题。shuffle 需在相同记录数量、任务/几何分层中打乱，避免把简单分布外破坏误解为因果证据。评估时突然清空记忆可能有分布偏移，训练中加入预先固定比例的空记忆样本，并报告 train/test protocol。

预先指定继续投入的开发标准，例如 3 个 seed 中至少 2 个方向一致、平均成功 AUC 的绝对差至少 0.03，且 wall-clock 没有明显恶化。它只是资源分配阈值，不是统计显著性或发表门槛。开发阈值在看下一轮新数据前固定；确认阶段按置信区间与预注册主对比判断。

如果只有预测提升，先做 reader 使用诊断、匹配 optimizer／BC 权重、观察 actor 是否忽略 context；允许一轮预定的修正预算。仍无控制收益就停止扩张 archive、改讲负结果或调整问题。若固定 response 最好，不要为了神经叙事隐藏它；先证明额外视觉和时间结构能解决它失败的场景。

单卡独立作业优先，不为小 actor／critic 强行使用两卡 DDP。将 GPU 与方法交叉分配或随机分配，避免方法始终绑定同一卡；不同作业独立输出目录、Ray 端口和 GPU 锁。正式报告给出环境 ticks 与 GPU-hours，不能拿 outer iteration 数作为统一交互成本。

7. 怎样验证记忆、迁移和旧经验失效

记忆收益。 从同一训练 checkpoint 出发冻结全部权重，固定实例初态与物理条件，做五次尝试。retain 只保留允许的 archive，clear 每次清空，shuffle 用等数量错配经验。成功后仍继续安排剩余尝试，避免后面的尝试只剩困难实例。分别报告第 k 次无条件成功率、先前失败条件下成功率、累计成功率；累计成功率自然随尝试数上升。

迁移收益。 相同 target weights 分别加载空 bank、相关 source bank、无关但等数量 bank、错误物理条件 bank。同时比较“已预训练 encoder 但空 bank”与未预训练初始化，区分权重迁移。source 使用训练任务，目标测试数据不得写回 source bank；target temporary memory 在实例之间清空。先限定同机器人、动作坐标、控制器与单位；跨 embodiment 不放进第一版贡献。

条件变化。 先只改变一个能从 simulator 读回验证的参数，避免同时改 stiffness、friction、delay 后无法解释。比较不清理、立即清理的 oracle 上界、固定遗忘、只用观测残差的清理。报告突变后前 K 步损失／失败、恢复所需有效 ticks、稳定条件误清理率、最终成功。延迟反馈绑定 prediction ID／generation；旧代反馈不能再次重置新代 memory。

接触与碰撞。 插入成功本来需要接触。不能把所有 contact 都当负事件；指定冲击阈值、积分时间和单位，区分正常约束接触、过大冲量和反复无效推进。真机没有力传感器时，q 响应只能提供歧义证据。先报告可测的“重复无效动作”和 simulator contact proxy，不写真实安全性提升。

8. 统计表必须怎么记

每个 episode 至少保存 method, training_seed, checkpoint, task, split, instance_id, attempt_id, physical_condition_id_for_analysis, memory_protocol, valid_ticks, success, intervention_ticks, wall_time。隐藏物理标签只进入分析文件，不能进入 policy observation。每个训练 checkpoint 同时记录训练 ticks、更新次数、GPU-hours、source data 成本。

主指标为按固定 interaction horizon 归一化的 success AUC；配合最终成功率、达到固定成功阈值所需 ticks 和 successes/hour。没达到阈值是右删失，不能丢掉后只平均达标 run。低成功率任务不要用成功回合平均长度掩盖大量失败。

统计以训练 seed 和实例分层做 paired bootstrap；同一 trajectory 的窗口不当独立样本，五次 retry 也不当五个独立训练 seed。三 seeds 只能提供较弱的不确定性估计，核心对比尽量补到五 seeds。100 回合在 p≈0.5 时单纯二项抽样 95% 半宽约 10 个百分点；若要证明最终成功率“不下降超过 5 个百分点”，需要更精确的评估，而不能用“不显著”代替等效。

预先固定一个主对比和主指标，其他确认性对比分组控制多重比较；预测头超参数只看 validation。最终 test 到实验冻结后再运行，不能每次调参都查看。
