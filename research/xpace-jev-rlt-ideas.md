## 2. 严格定义 physical 与 recoverability

本提案中的 physical 指**动作与接触相关的可测后果**，例如物体随末端移动、接触建立/丢失、稳定支撑、滑移趋势。它不要求显式拟合摩擦系数，也不把语义任务是否理解正确全部归入物理问题。

定义历史 h_t 为部署时可得的图像/特征、本体状态、已发出且实际执行的动作、有效执行时长与掩码；g 为任务。先执行预注册候选 chunk a，再用固定参考策略 π_ref 继续至多 B 秒。若在规定约束下完成任务，标记 y_B=1，否则为0。探针预测：

`p_B = P(y_B = 1 | h_t, g, a, π_ref, controller, B)`

这是**给定策略与执行接口的有限预算可恢复性**，不是环境内在不变属性。如果环境与策略完全确定，一次 rollout 只给0/1；要谈概率须指定初态或执行噪声分布并做重复试验。

成功概率本身接近有限时域 value，**不能仅换名称就称物理直觉**。物理含义需要接触事件辅助标签、相似图像但不同接触历史的困难样本、可控物理变化下的测试，以及对控制的实证贡献。

可恢复性低也不自动说明“应该退让”。要推荐某恢复动作，需要比较同状态不同候选的实际后果，而不仅发现原动作不好。目标物识别错、规划错与局部接触错应分开报告。

## 3. 第一步：用最少成本证伪表示假设

选择 RLT 已跑通且有稳定成功/失败的两个任务，一个抓持保持任务、一个接触后推进/恢复任务；不以任务名字替代视频诊断。

1. 从不同 episode 的接触前、接触建立后和失败前取开发状态；至少保留独立 episode 划分，不能把同轨迹相邻帧分到训练和测试。
2. 开发阶段可试末端横向偏移 5/10 mm；是否可执行由任务与控制器验证。15/20 mm 作为候选留出强度，全部阈值在测试前冻结。不要把穿模/不可达样本算作算法失败。
3. 候选包括原动作，以及相同表示中有界改变的动作。每个候选都在真实物理仿真中执行，记录实际状态变化；不可把命令差当成实际动作差。
4. 接着运行固定参考策略，给出 y_B 与接触事件标签；候选分支的全部环境步数都计入数据成本。B 在开发集按正常完成时长固定，所有组相同。
5. 比较 RLT token+公共历史、同容量通用历史编码、action-side token+公共历史。任务条件和预测头容量一致；需要时增加通用 future-feature 监督对照。

RoboTwin 状态分支是实现 gate：快照必须包含机器人/物体状态、速度、控制器内部状态、时间和随机数状态；先确认复原后相同动作产生一致轨迹。若尚不支持可靠快照，就对同 seed 重放同一前缀并验证状态一致性；验证失败的分支不作成对因果样本。

标签与 oracle 可以读仿真真值；主模型不能因此获得真值输入。没有触觉或 wrench 时，不应在训练历史中加入部署不可得的接触量。用图像/本体历史预测这些量并在测试时保持输入边界。

指标：Brier score、失败类 PR-AUC、预注册误报率下的失败召回、不同扰动强度下校准；辅以接触事件准确性。PR-AUC 同时报告类别基率；同状态多分支以 episode 为聚类单元统计区间。

**停止条件：**普通历史编码已解释全部收益，或 action-side 表示只在特权输入下有效，则不要继续按“专用物理 token”叙事扩张，先检查监督和部分可观测性。

## 4. 第二步：恢复标签与数据怎么产生

XPACE 的核心可借鉴点是恢复经验，不要求我们现在训练视频生成器。RoboTwin 已有物理仿真，先用它验证数据价值。

| 数据 | 后果预测 | Critic / RL replay | 行为克隆目标 |
|---|---|---|---|
| 正常成功 transition | 使用 | 使用真实奖励与终止信息 | 可使用 |
| 物理有效的失败/低进展 transition | 使用 | 保留实际结果，不改成成功 | 不自动正向模仿 |
| 偏离动作段 | 使用 | 保留实际结果 | 不当作恢复专家动作 |
| 独立执行验证有效的恢复段 | 使用 | 使用真实仿真奖励 | 可以增加恢复 imitation loss |
| 视频模型生成但未验证片段 | 另设模型误差实验 | 不直接灌入主表真实 replay | 不自动视为专家 |

恢复候选来源必须明示：任务专家、规划器或有界搜索各有人工/计算成本。不能假定把专家原命令后半段直接拼上就能恢复。

接触后“返回同一末端姿态”不足以接专家后续。应继续实际执行后续动作，检查物体是否仍被握住、位姿/速度是否合理、约束是否满足和任务是否完成。机器人和物体实际轨迹连贯后才接受为恢复样本；恢复失败仍保留为负例，不能从数据账本消失。

第一阶段可以冻结编码器，只用其预测给开发候选池排序；选择规则在独立训练/验证集定好。随机组与定向组使用同一候选池、相同总仿真预算和相同保留样本数。池的生成、筛选和失败尝试都算成本，不能只统计保留的成功轨迹。

定向采集不能简单选“最不确定”：不确定可能来自坏传感器或不可学噪声。优先结合基线真实失败密度、可验证恢复率及覆盖多样性；具体评分是待消融的方法变量，而非已确定最优公式。

## 5. 五组实验分开表示与数据的贡献

| 组别 | 表示 | 额外训练数据 | 目的 |
|---|---|---|---|
| C0 | RLT + 公共历史 | 原始数据再训练，匹配更新预算 | 排除只是多训练了一段 |
| C1 | RLT + 公共历史 | 随机有效恢复 | 普通数据增强收益 |
| C2 | RLT + 公共历史 | 定向有效恢复 | 在表示不变时检验数据选择 |
| C3 | 后果监督 token + 公共历史 | 随机有效恢复 | 在数据规则不变时检验表示 |
| C4 | 后果监督 token + 公共历史 | 定向有效恢复 | 检验二者组合与交互 |

C1–C4 是 2×2。若用 token 产生定向池，先用独立训练集得到**一份固定的选择器和同一份定向数据**给 C2/C4；否则表示变量与数据变量混在一起。选择器训练成本入账。在线自适应选择是下一阶段单独实验。

C0匹配再训练量与在线交互预算，但不额外采集恢复数据，其总成本应单列；不能把它描述为与C1–C4完全相同的总数据成本。C1–C4使用同一候选生成预算，并记录筛选拒绝率与保留样本数。

各组固定 base checkpoint、归一化、actor/critic 结构、H/C、参考刷新、奖励、更新/交互比例、离线数据曝光量及评测协议；新增参数使用同容量非物理对照。恢复 imitation loss 的权重/采样比例一致。XPACE 的8%只可作为候选起点，不照搬成RLT的最优值。

离线训练 token 后先冻结它，在线仍只更新原计划中的 actor/critic，以保持归因。若要 token 随经验更新，另加独立消融，不与首轮结果混合。

建议小规模实施：2任务×3训练seed×5组=30次训练；在线预算沿用已锁定 RLT 的每任务 B_online。若尚未锁定，先根据吞吐与成功曲线做预算 pilot，不把GPU型号换算成未经测量的训练时长。正式证据再扩至至少4任务、5训练seed；每checkpoint评测使用相同独立seed，禁用探索与参数更新。

主指标：成功率对累计交互量的曲线面积、固定预算末端成功率、达到预注册成功阈值的交互量（未达到者保留为删失）、物理失败数与全部数据成本。恢复专用评测使用未参与采集的扰动状态；正常任务成功率用于检查是否损害原能力。

不只展示最终最好checkpoint；预先固定评测间隔和选模规则，区间以训练seed为主，episode数量不能冒充独立训练次数。

## 6. 实验结果如何决定论文写法

| 结果 | 允许的解释 | 下一步 |
|---|---|---|
| C1明显好于C0，C3/C4无额外收益 | 恢复数据有效，token价值未证 | 考虑数据构造/评估贡献 |
| C2优于C1且C4优于C3 | 定向选择改善样本效率 | 检查收益是否覆盖选择器成本 |
| C3优于C1且C4优于C2 | 表示在匹配数据下有增益 | 扩展物理变化与同容量对照 |
| 预测更好但C3/C4不更好 | 表示学到信息，控制价值不足 | 检查actor使用方式或换目标 |
| 仅 oracle 仿真预演有效 | 物理真值/规划预算带来增益 | 不宣称部署可得 token 能力 |

新意判断还需对比 WM-DAgger、DAgger、现有 value-guided 策略和历史适应表示。这里给的是可证伪候选，不保证可发表或已避开全部近邻。

## 7. 与两种自进化目标对齐

**同任务越做越好：**在接触条件变化后，以相同交互预算比较学习曲线，并加入冻结参数组。更新对象、数据来源和预算明确；不要求每一轮单调提高。

**新任务也能不断学会：**按任务身份划分源任务和目标任务，禁止把目标任务恢复片段提前混入表示/选择器训练。比较从共享表示与从头适应所需交互量，再测源任务保留。新seed、新物体、同任务新摩擦、新任务分别标记。

只有在固定评测序列中体现学习效率提升、旧任务保留和跨任务复用，才逐步讨论成长性。增加一个 verifier 或一次再训练本身不构成递归自进化证据。
